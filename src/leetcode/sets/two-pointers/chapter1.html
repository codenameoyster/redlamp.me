Two Pointers: указатели идут с двух краёв Array навстречу друг другу. Каждый ход исключает пары, которые точно не дадут ответ.

1. Задача про пару с суммой

LeetCode 167. Array numbers отсортирован по неубыванию: каждое следующее число не меньше предыдущего. Найдите два числа с суммой target и верните их номера с единицы. Ответ всегда есть, и он один.

  • [2, 7, 11, 15], target = 9: ответ [1, 2], потому что 2 + 7 = 9.
  • [2, 3, 4], target = 6: ответ [1, 3].
  • [-1, 0], target = -1: ответ [1, 2].

Модель затрат. n - длина входа. Считаем сложение, сравнение и доступ по индексу операциями O(1): размеры чисел ограничены. O(f(n)) задаёт верхнюю границу роста затрат; отдельно указываем худший или ожидаемый случай.

Дополнительная память - максимум одновременно хранимых рабочих данных, без входа и ответа. Учитываем временные копии и рабочую память Sorting. Постоянное число индексов занимает O(1) в этой модели; число битов у неограниченных Python int может расти.

Для ориентира: Linear Scan ищет максимум, начиная с первого элемента. Каждый из остальных n-1 элементов сравнивается с текущим максимумом: O(n) времени и O(1) дополнительной памяти, ответ - одно число. Для [2,7,11,15] это 3 сравнения. Обход по индексам не создаёт копию a[1:], которая потребовала бы O(n) памяти.

Brute Force для пары проверяет до n(n-1)/2 сумм: O(n²) времени и O(1) дополнительной памяти. При n = 30 000 это 449 985 000 пар. Обычный Linear Scan с одним максимумом не решает Two Sum. Hash Table хранит уже встреченные числа, а Two Pointers использует готовый порядок.

3. Правило и инвариант

Правило. Сумма меньше target: l += 1. Сумма больше target: r -= 1. Сумма равна target: пара найдена.

Инвариант это утверждение, которое верно перед каждым ходом. Здесь он такой: если нужная пара есть, она внутри окна от l до r. Каждый ход выбрасывает только строку или столбец без ответа, поэтому инвариант не ломается.

a = [1, 4, 5, 7, 10, 12, 16]
target = 15
l, r = 0, len(a) - 1
while l < r:
    s = a[l] + a[r]
    if s == target:
        print([l + 1, r + 1])  # в 167 номера с единицы
        break
    if s < target:
        l += 1  # вся строка l меньше target
    else:
        r -= 1  # весь столбец r больше target

Время: расстояние r-l изначально равно n-1. Каждая неудача уменьшает его на 1, успех завершает поиск. Поэтому вычислений суммы не больше n-1: O(n) в худшем случае. Дополнительная память: l, r, s занимают O(1). Ответ содержит два индекса: O(1). В трёх примерах раздела 1 вычисляются соответственно 3, 1 и 1 сумма.

Hash Table делает n проверок наличия дополнения и n добавлений. При хороших хешах поиск ожидаемо O(1); расширение таблицы даёт амортизированную стоимость добавления. Много совпадающих хешей может дать O(n²) за весь проход. Разные единицы в таблице нельзя напрямую сравнить как время.

Python list.sort() меняет вход, но в худшем случае использует O(n) рабочих ячеек. sorted() ещё создаёт копию. Поэтому Sorting плюс проход требует O(n log n) времени и O(n) дополнительной памяти. n log₂ n - модель роста, не точный счёт операций Python. Если нужны исходные индексы, храните пары (value, index) в O(n) памяти или индексы в Hash Table.

4. Когда форма работает

LeetCode 11. Даны высоты линий [1, 8, 6, 2, 5, 4, 8, 3, 7], линии стоят на позициях 0..8. Найдите две линии, между которыми помещается больше всего воды. Площадь воды равна высоте меньшей линии, умноженной на разность позиций. Для l = 0 и r = 8 площадь min(1, 7) · 8 = 8. Любая другая пара с линией 0 более узкая, а высота у неё не больше 1. Значит, её площадь не больше 7. Строку 0 можно выбросить: она не лучше уже найденного.

В задаче 167 строка была «вся меньше target». В задаче 11 строка «не лучше уже найденного». Причины разные, но приём один.

Время: n - число линий. Полный проход делает n-1 вычислений площади и n-1 сужений: O(n). При n = 9 это 8 площадей, максимум 49. Brute Force проверяет 9 · 8 / 2 = 36 пар: O(n²). Дополнительная память: два индекса, текущая площадь и лучший результат: O(1); ответ - одно число. Если двигать более высокую линию, время останется O(n), но доказательство нарушится и ответ может быть неверным.

Container With Most Water, n = 9Вычислений площадиДополнительная память

Two Pointers требует причины, по которой исключённые кандидаты не нужны. Для Two Sum это порядок значений, для площади - уменьшение ширины при фиксированной меньшей высоте.

Подсказка 1

В ответе нужно количество, исходные номера не важны. Sorting допустим.

Те же l и r, что в 167. Сумма меньше k: самое большое число в окне не помогло числу a[l]. Значит, a[l] не подойдёт никому.

Сумма равна k: используйте оба числа и двигайте оба указателя. Числу x подходит только k-x. Если несколько экземпляров подходят, они взаимозаменяемы; выбор крайних не уменьшает число будущих пар.

Boats to Save People: Sorting и Greedy

LeetCode 881: n человек, в лодке не больше двух, каждый вес ≤ limit. После Sorting сравните самого лёгкого с самым тяжёлым. Если они не помещаются вместе, тяжёлый не поместится ни с кем и едет один. Если помещаются, посадите их вместе. Пусть h - вес самого тяжёлого. Если раньше он ехал с человеком веса y, а самый лёгкий - с человеком веса x, после обмена x + y ≤ h + y ≤ limit. Число лодок не растёт. Случаи одиночных лодок тоже не увеличивают их число.

Веса; limit = 3ЛодкиРабота после Sorting
[3,2,2,1](3), (1,2), (2)2 проверки пары, 3 лодки

Каждый человек используется один раз: проход O(n). Время с Sorting O(n log n), дополнительная память Python O(n), ответ - одно число. Если целые веса лежат в 1..W и W мал, Counting с W частотами заменяет Sorting: n добавлений частоты, O(W) переходов между весами и O(n) посадок. Итого O(n+W) времени, O(W) памяти. В примере n = 4, W = 3: 4 добавления и 3 счётчика.

6. Что нужно запомнить

  • l идёт с начала, r с конца, цикл идёт, пока l < r.
  • Сумма меньше target: l += 1. Больше: r -= 1. Каждый ход выбрасывает целую строку или целый столбец пар.
  • Инвариант: если ответ есть, он внутри окна от l до r.
  • В Two Sum вычислений суммы не больше n-1. В примере 5 сумм и 4 хода; это разные счётчики.
  • Считайте подготовку: Sorting меняет время на O(n log n), а Python требует до O(n) рабочей памяти.

7. Как решать задачи этой главы

  1. Прочитайте условие. Array отсортирован? Если нет, допустим ли Sorting и нужны ли исходные индексы?
  2. Для каждого хода скажите вслух, какую строку или какой столбец он выбрасывает и почему там нет ответа.
  3. Проверьте правило на маленьком примере на бумаге. Только потом пишите код.
