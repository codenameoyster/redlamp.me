2. Два условия для линейного прохода

n - число элементов одного Array, n и m - длины двух входов. Числа и символы считаем ограниченного размера, операции с ними имеют постоянную цену. Дополнительная память - максимум рабочих ячеек без входа и результата. Временные копии и буфер Sorting входят в эту оценку.

LeetCode 443 сжимает a a a b b в a 3 b 2. Внешний цикл идёт по группам, внутренний проходит одну группу. Внешний цикл делает 2 итерации, а read увеличивается 5 раз.

Условие 1. Суммарно указатели двигаются O(n) или O(n + m) раз. При постоянной работе на движение весь проход линейный. Отдельно посчитайте внешние перезапуски, копии и подготовку данных.

Счётчик «Прочитано» считает обработанные элементы, то есть сдвиги read. Это не число всех обращений к chars: проверка границы группы может читать следующий символ ещё раз. Для g групп условие chars[read] == chars[start] выполняет n успешных и g - 1 неуспешных сравнений. Здесь это 5 + 1 = 6 сравнений и 4 записи.

Время String Compression: O(n): n продвижений read, не больше n записей и суммарно O(n) цифр длин групп. Дополнительная память: индексы O(1), но str(count) создаёт до O(log(n + 1)) временных символов для самой длинной группы. Вход chars занимает O(n), ответ лежит в его префиксе, возвращается одно число. Для групп длины 3 и 2 одновременно нужна одна временная цифра.

Как выполнить строгое требование O(1) для String Compression

Пишите цифры длины группы арифметически: найдите старший десятичный делитель и извлекайте по одной цифре. Тогда не нужна растущая String от str(count), остаётся постоянное число переменных в модели ограниченных чисел. Для группы из 1000 символов str(1000) хранит четыре временных символа. Отдельный буфер всего ответа потребовал бы O(n) памяти.

В задаче 167 сумма 1 + 12 = 13 меньше 15, и ход l исключил строку 0 таблицы пар. В задаче 26 повтор остаётся между write и read. При Merge выбранное меньшее число уходит в ответ.

Условие 2. Перед ходом объясните, почему исключённый элемент больше не нужен. Это сохраняет инвариант. Линейное число движений само по себе не доказывает правильность.

На рисунке оба варианта делают одно вычисление суммы и один сдвиг. Проверки ==, затем < дают два сравнения значений. Только верный вариант сохраняет пару 5 + 10. Для всего отсортированного Array длины n нужно не больше n - 1 вычислений суммы: O(n) времени, O(1) рабочей памяти и два индекса ответа. Две нарисованные копии нужны для объяснения, алгоритм их не создаёт.

3. Другие применения и ограничения

Two Sum без порядка

Нужно вернуть исходные индексы. Hash Table через Python dict хранит значение и его индекс. До добавления nums[i] ищите X - nums[i]: тогда один индекс не используется дважды. n - длина nums, u - число разных сохранённых значений. До n поисков и n добавлений дают ожидаемое O(n) время и O(u) рабочую память. При плохом распределении хешей время может стать O(n²). Вход O(n), ответ - два индекса, O(1).

Sorting сохраняет индексы, если сохранить пары

Для того же ответа можно выполнить Sorting пар (значение, исходный индекс) и затем Two Pointers. Время O(n log n), дополнительная память Python O(n) для пар и Sorting. Здесь четыре пары дают [(1,1),(2,0),(5,2),(7,3)]. Вычисляем суммы 8, затем 6 и возвращаем исходные индексы [1,2]. Это два вычисления суммы после подготовки; проверки ==, затем < дают три сравнения значений. Brute Force проверяет до n(n - 1)/2 пар, O(n²) времени и O(1) рабочей памяти: при n = 4 до 6 проверок, при n = 8 до 28. Обычный проход без сохранения значений не решает общий Two Sum.

Разворот Array на месте

Меняйте крайние элементы и двигайте оба указателя внутрь. Для n элементов нужны ровно floor(n/2) обменов, по две записи в каждом: O(n) времени и O(1) дополнительной памяти. Вход занимает O(n), результат остаётся в нём. Для [1,2,3,4,5] это два обмена (1,5) и (2,4), четыре записи, ответ [5,4,3,2,1]. Срез a[::-1] тоже требует O(n) времени, но создаёт новый результат из n элементов; присваивание a[:] = a[::-1] использует O(n) временной памяти.

Поиск положительной разности

В отсортированном Array длины n ищем a[j] - a[i] = d, где d > 0, i < j. Начните с i = 0, j = 1. Если разность мала, двигайте j; если велика, двигайте i. При i = j увеличьте j без проверки разности. Каждый указатель увеличивается не больше n раз: O(n) времени, O(1) дополнительной памяти. Вход занимает O(n), ответ - два индекса. Sorting неупорядоченного входа добавит O(n log n) времени и O(n) рабочей памяти Python.

Sliding Window с положительными числами

Найдите самый длинный непрерывный Subarray с суммой не больше S, где S ≥ 0. Храните сумму окна. Добавьте правое число; пока сумма больше S, вычитайте левое и двигайте левую границу. При добавлении положительного числа сумма только растёт, поэтому исключённое начало больше не даст допустимого окна при дальнейших расширениях.

Сравнение Sliding Window с Brute Force

Brute Force с накоплением суммы для каждого начала делает n(n + 1)/2 добавлений: для n = 4 это 10, против 4 добавлений и 3 вычитаний в примере. Он требует O(n²) времени и O(1) рабочей памяти. Если заново суммировать каждый Subarray, число посещений элементов равно n(n + 1)(n + 2)/6: здесь 20, в общем O(n³).

3Sum: внешний цикл меняет цену

n = len(nums), q - число разных троек ответа. После Sorting фиксируйте nums[i] и запускайте Two Pointers справа от i. Пропускайте равные значения i и повторы у границ после найденной тройки. Время: каждый запуск требует O(n), но запусков O(n). Общая оценка O(n²), включая O(n log n) Sorting. Без пропусков верхняя граница проверок сумм равна (n - 2) + ... + 1 = (n - 1)(n - 2)/2. Вход O(n), дополнительная память Python O(n) для Sorting, ответ O(q) троек, то есть 3q чисел.

В примере пропускаем повторный i со значением -1. Для фиксированных -4, -1 и 0 получаем 4 + 2 + 1 = 7 проверок суммы, если не добавлять раннюю остановку по знаку.

Почему не проверять готовый ответ целиком

Brute Force троек имеет O(n³) время. Hash Table для каждой фиксированной позиции даёт ожидаемое O(n²) время, но требует O(n) рабочего места и отдельного удаления повторов. При Sorting одинаковые значения стоят рядом, поэтому повторы можно пропускать по соседям. Поиск каждой новой тройки во всём ответе добавляет зависимость от q и может нарушить O(n²).

6. Что нужно запомнить

  • Три формы: навстречу, читатель и писатель, две последовательности.
