Two Pointers с ролями read и write: один индекс читает Array, другой указывает место для следующего нужного числа.

1. Задача: убрать повторы на месте

LeetCode 26. Array nums отсортирован по неубыванию. Уберите повторы, сохранив порядок. Верните k, количество разных чисел. Первые k ячеек должны содержать ответ, остальная часть не важна.

  • [1, 1, 2]: k = 2, в начале [1, 2].
  • [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]: k = 5, в начале [0, 1, 2, 3, 4].

Модель затрат: n - длина Array, k - число оставленных элементов. Числа имеют ограниченный размер; сравнение, запись и доступ по индексу стоят O(1). Дополнительная память - максимум рабочих данных без входа и ответа. Здесь индексы занимают O(1), а k элементов результата уже лежат во входном Array. Это in-place. Копия nums[:k] для вывода или проверки потребует O(k) времени и O(k) памяти результата.

2. Трассировка по шагам

Возьмите [1, 1, 2, 3, 3]. Первое число остаётся всегда, поэтому write = 1. Указатель read идёт с ячейки 1 и сравнивает число с последним оставленным, это nums[write - 1].

readЧислоПоследнее оставленноеДействиеwriteArray
111повтор, не пишем1[1, 1, 2, 3, 3]
221пишем в ячейку 12[1, 2, 2, 3, 3]
332пишем в ячейку 23[1, 2, 3, 3, 3]
433повтор, не пишем3[1, 2, 3, 3, 3]

Ответ: k = 3, в начале [1, 2, 3]. Выполнены 4 сравнения чисел и 2 записи в Array. Первое число осталось без записи. Рисунки показывают состояние и накопленные счётчики после обработки read.

  • Слева от write лежит готовый ответ.
  • Между write и read лежит мусор: эти числа уже прочитаны и больше не нужны.
  • Справа от read лежат числа, которые ещё не прочитаны.

Равные числа идут подряд, поэтому достаточно сравнить с последним оставленным. Время: n-1 сравнений и k-1 записей, где k ≤ n, дают O(n). Дополнительная память: два индекса и постоянное число временных значений, O(1). При n = 8 будет 7 сравнений, при n = 16 будет 15. В примерах раздела 1: 2 сравнения и 1 запись; 9 сравнений и 4 записи. Новый list тоже можно построить за O(n), но он хранит O(k) выходных элементов и не выполняет условие in-place.

3. Роли, инвариант и шаблон

read последовательно проверяет элементы. write показывает место, куда пойдёт следующее нужное число.

Инвариант. Первые write элементов - готовый ответ для прочитанной части. При записи write ≤ read, поэтому непрочитанные значения сохраняются. Запись nums[0:write] здесь обозначает диапазон; вычислять этот Python slice в цикле не нужно.

Обычно от задачи к задаче меняется только условие «нужно оставить».

write = 0
for read in range(len(nums)):
    if нужно_оставить(nums[read]):
        nums[write] = nums[read]
        write += 1
return write

В Remove Element (27) условие - nums[read] != val. Для [3,2,2,3] и val = 3 выполнены 4 проверки условия и 2 записи. Ответ k = 2, в начале [2,2].

Время шаблона: n проверок условия и k записей: O(n), если само условие стоит O(1). Код читает nums[read] для каждой проверки и ещё раз для каждой записи: n+k чтений этой ячейки. При n = 10 указатели суммарно сдвигаются не больше 20 раз; это не число всех инструкций. Дополнительная память: O(1). Ответ хранится в первых k входных ячейках; возвращаемое k занимает O(1). Цикл не вызывает удаление и не сдвигает остаток Array.

Remove Element: другие способы

Порядок не важен, поэтому найденный val можно обменять с последним активным элементом, уменьшить правую границу и проверить полученное значение снова. Неизвестная часть сокращается на каждом шаге: O(n) времени, O(1) дополнительной памяти. Для [0,1,2,3], val = 0, один обмен даёт [3,1,2] в начале: 2 записи вместо 3 в стабильном шаблоне. Простая замена значением с конца требует 1 запись, если старое значение сохранять не нужно. Повторные удаления из середины Python list могут сдвинуть (n-1)+(n-2)+…+1 элементов: O(n²) времени и O(1) дополнительной памяти. При удалении всех 4 элементов с начала это 6 сдвигов. Новый отфильтрованный list строится за O(n) и хранит O(k) элементов результата.

Remove Duplicates from Sorted Array II: оставить два экземпляра

LeetCode 80: если write < 2, оставляйте число. Иначе сравните его с nums[write-2]. Совпадение означает, что два таких числа уже оставлены: благодаря порядку все повторы идут подряд. Начните с write = min(2,n) и read = 2. Тогда n≥2 даёт ровно n-2 сравнений и k-2 записей. Время O(n), дополнительная память O(1), ответ в исходном Array.

String Compression: работа с группами

В задаче 443 read проходит группы одинаковых символов. n - число символов, g - максимальная длина группы. aaabb даёт a3b2: 5 входных символов, 2 группы и 4 записи результата. Все группы вместе содержат n символов, поэтому проход и записи требуют O(n) времени. Ответ занимает первые k ≤ n ячеек входа. Индексы занимают O(1), но str(groupLength) создаёт до O(log(g+1)) временных символов, в худшем случае O(log(n+1)) дополнительной памяти. Здесь максимальное число 3 занимает один символ. Сборка отдельной String через list и join тоже линейна, но добавляет O(n) рабочих ячеек и O(k) символов результата.

Move Zeroes: перенесите все нули в конец, порядок остальных чисел не меняйте. Например, [0, 1, 0, 3, 12] становится [1, 3, 12, 0, 0]. Если вы уже решали эту задачу, сегодня задание другое.

Подсказка 1

Какое число здесь «нужно оставить»? Любое, кроме нуля.

Подсказка 2

Если просто писать nums[write] = nums[read], нули потеряются. Что сделать вместо записи, чтобы нули сами уехали вправо?

Подсказка 3

Проверьте на [0, 1, 0, 3, 12]: после каждого шага между write и read должны лежать только нули.

Время: n проверок и k обменов для k ненулевых чисел дают O(n). Каждый обмен пишет в две ячейки, даже когда read == write: 2k записей. Дополнительная память: два индекса и временное значение для обмена, O(1). Ответ занимает тот же Array из n элементов. Ненулевые числа сохраняют порядок, а между write и read остаются нули.

Как сократить записи Move Zeroes

Проверка read != write перед обменом убирает обмены с собой. В [1,2,3,4,5] останется 5 проверок ненулевого значения, но записей будет 0 вместо 10. Другой способ: переписать k ненулевых чисел в начало, затем заполнить n-k ячеек нулями. Без защиты от записи в себя это ровно n записей: для [0,1,0,3,12] получается 3 + 2 = 5 вместо 6 при обменах. Оба способа требуют O(n) времени, O(1) дополнительной памяти и используют вход для результата.

5. Вызов: LeetCode 75

Sort Colors: Array содержит только 0, 1 и 2. Dutch National Flag начинает с low = mid = 0, high = n-1. До low стоят нули, в диапазоне [low, mid) - единицы, от mid до high включительно - неизвестная часть, после high - двойки.

  • При 0 обменяйте mid с low и увеличьте оба индекса.
  • При 1 увеличьте mid.
  • При 2 обменяйте mid с high и уменьшите high. Новый элемент в mid ещё неизвестен, поэтому mid остаётся.

Время: неизвестная часть уменьшается ровно на 1, значит n итераций и не больше n обменов: O(n). В примере n = 6: 6 итераций, 4 обмена и 8 записей, включая обмены с собой. Если проверять сначала 0, потом 1, будет 10 сравнений значений. Дополнительная память: три индекса и временное значение, O(1). Ответ хранится во входном Array.

Другие способы Sort Colors

Counting Sort с тремя счётчиками делает n добавлений частот, затем n записей: O(n) времени и O(1) дополнительной памяти. В примере это 6 добавлений, 6 записей и 3 счётчика. Он проходит вход дважды, но тоже хранит ответ на месте. Общий Python Sorting даёт O(n log n) времени и O(n) рабочей памяти в худшем случае; ограничение на три значения позволяет обойтись без него.

6. Что нужно запомнить

  • read читает всё, write пишет только нужное. Оба идут слева направо.
  • Слева от write готовый ответ, между write и read мусор, справа от read непрочитанное.
  • write никогда не обгоняет read, поэтому запись не портит непрочитанное.
  • Обычно от задачи к задаче меняется только условие «нужно оставить».
  • Считайте проверки, записи и дополнительную память отдельно. Линейное число движений даёт O(n) время только при O(1) работе на каждом движении.

7. Как решать задачи этой главы

  1. Найдите в условии слова «на месте» (in-place) или «память O(1)». Это сигнал для читателя и писателя.
  2. Запишите одной фразой условие «нужно оставить» и проверьте его на примере из условия.
  3. Пройдите пример на бумаге и после каждого шага назовите три зоны. Только потом пишите код.
