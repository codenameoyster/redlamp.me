Оба указателя идут слева направо: read читает каждое число, а write пишет только те числа, которые нужно оставить.

1. Задача: убрать повторы на месте

LeetCode 26. Массив nums отсортирован по неубыванию. Уберите повторы так, чтобы каждое число осталось один раз, а порядок не изменился. Верните k, количество разных чисел. Первые k ячеек должны содержать ответ, что лежит дальше, неважно.

  • [1, 1, 2]: k = 2, в начале [1, 2].
  • [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]: k = 5, в начале [0, 1, 2, 3, 4].

Дополнительная память только O(1). Новый список заводить нельзя, ответ пишется в тот же массив. Такие задачи называют задачами «на месте».

2. Трассировка по шагам

Возьмите [1, 1, 2, 3, 3]. Первое число остаётся всегда, поэтому write = 1. Указатель read идёт с ячейки 1 и сравнивает число с последним оставленным, это nums[write - 1].

readЧислоПоследнее оставленноеДействиеwriteМассив
111повтор, не пишем1[1, 1, 2, 3, 3]
221пишем в ячейку 12[1, 2, 2, 3, 3]
332пишем в ячейку 23[1, 2, 3, 3, 3]
433повтор, не пишем3[1, 2, 3, 3, 3]

Ответ: k = 3, в начале [1, 2, 3]. Посмотрите на массив после каждого шага. Он делится на три зоны.

  • Слева от write лежит готовый ответ.
  • Между write и read лежит мусор: эти числа уже прочитаны и больше не нужны.
  • Справа от read лежат числа, которые ещё не прочитаны.

3. Роли, инвариант и шаблон

read читает каждую ячейку ровно один раз. write показывает место, куда пойдёт следующее нужное число.

Инвариант. nums[0:write] это готовый ответ для уже прочитанной части. В момент записи всегда write ≤ read, поэтому запись не портит непрочитанное.

Обычно от задачи к задаче меняется только условие «нужно оставить».

write = 0
for read in range(len(nums)):
    if нужно_оставить(nums[read]):
        nums[write] = nums[read]
        write += 1
return write

В задаче 26 нужно оставить число, которое не равно последнему оставленному. В задаче 27 нужно оставить число, которое не равно val. В задаче 443 (String Compression: aaabb → a3b2) работает тот же приём, только read за один шаг съедает целую группу одинаковых букв.

Сколько шагов делает каждый указатель? read проходит массив один раз, write не обгоняет read. Для массива из 10 чисел оба вместе делают не больше 20 шагов. Это O(n).

Вопрос на будущее: что поменять в коде, если каждому числу можно остаться два раза? Это задача 80.

4. Практика: LeetCode 283 заново

Move Zeroes: перенесите все нули в конец, порядок остальных чисел не меняйте. Например, [0, 1, 0, 3, 12] становится [1, 3, 12, 0, 0]. Если вы уже решали эту задачу, сегодня задание другое.

5. Вызов: LeetCode 75

Sort Colors: в массиве только 0, 1 и 2. Расставьте их по порядку за один проход, без sort. Например, [2, 0, 2, 1, 1, 0] становится [0, 0, 1, 1, 2, 2]. Здесь один читатель и два писателя: три указателя и зоны для нулей, единиц и двоек. Сначала запишите словами, что лежит в каждой зоне. Потом пишите код.

6. Что нужно запомнить

  • read читает всё, write пишет только нужное. Оба идут слева направо.
  • Слева от write готовый ответ, между write и read мусор, справа от read непрочитанное.
  • write никогда не обгоняет read, поэтому запись не портит непрочитанное.
  • Обычно от задачи к задаче меняется только условие «нужно оставить».

7. Как решать задачи этой главы

  1. Найдите в условии слова «на месте» (in-place) или «память O(1)». Это сигнал для читателя и писателя.
  2. Запишите одной фразой условие «нужно оставить» и проверьте его на примере из условия.
  3. Пройдите пример на бумаге и после каждого шага назовите три зоны. Только потом пишите код.
