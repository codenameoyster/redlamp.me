У каждой из двух последовательностей свой указатель, и каждый указатель идёт в одну сторону.

1. Задача: слить два массива

Даны два массива a и b, оба отсортированы по неубыванию. Соберите из них один отсортированный массив. Вызывать sort нельзя.

Пример: a = [1, 3, 5, 8], b = [2, 3, 6, 7, 9]. Ответ: [1, 2, 3, 3, 5, 6, 7, 8, 9].

2. Трассировка по шагам

Указатель i стоит на первом числе a, указатель j на первом числе b. На каждом шаге сравниваем a[i] и b[j], берём меньшее и сдвигаем его указатель.

Массив a закончился. Остаток b это [9]. Он уже отсортирован и не меньше всего взятого, поэтому его дописываем целиком.

i = j = 0
out = []
while i < len(a) and j < len(b):
    if a[i] <= b[j]:
        out.append(a[i])
        i += 1
    else:
        out.append(b[j])
        j += 1
out += a[i:] + b[j:]

3. Инвариант и цена

Почему на каждом шаге хватает одного сравнения? a[i] это самое маленькое из оставшихся чисел a. b[j] это самое маленькое из оставшихся чисел b. Меньшее из них самое маленькое из всех оставшихся чисел.

Инвариант. Всё, что уже лежит в out, не больше всего, что осталось. Всё левее i и левее j уже обработано и больше не нужно.

Каждый шаг двигает один указатель вперёд, назад никто не ходит. В примере 4 + 5 = 9 чисел, и указатели сделали 9 шагов: 8 в цикле и 1 при дописывании остатка. Для массивов длины n и m шагов n + m.

4. Подсчёт вместо слияния

Новая задача: для каждого b[j] посчитайте, сколько чисел в a строго меньше него. Возьмите a = [1, 3, 5, 8] и b = [2, 3, 6]. Ответы: для 2 это 1, для 3 это 1, для 6 это 3.

Посмотрите на слияние. В момент, когда вы берёте b[j], левее i лежат ровно те числа из a, которые меньше b[j]. Ответ для b[j] это i. Только при равенстве сначала надо брать из b, иначе 3 из a попадёт в счёт для 3 из b. Условие станет a[i] < b[j].

Та же форма работает в других задачах. LeetCode 392: один указатель идёт по строке s, второй по строке t. LeetCode 1768: буквы двух слов берут по очереди. LeetCode 349: общие числа двух отсортированных массивов. Двигайте указатель там, где число меньше.

5. Практика: LeetCode 88

Merge Sorted Array. Задача лёгкая, но с ловушкой. Массив nums1 имеет длину m + n. В первых m ячейках лежат числа, последние n ячеек пустые, там нули. В nums2 лежит n чисел. Оба отсортированы. Слейте nums2 в nums1 на месте, возвращать ничего не надо.

Свободное место лежит справа. С какого числа тогда начинать: с самого маленького или с самого большого?

Подсказка 2

Три указателя: i = m - 1 читает nums1, j = n - 1 читает nums2, write = m + n - 1 пишет. Все трое идут влево.

Когда можно остановиться: когда закончился nums1 или когда закончился nums2? Что в этот момент уже лежит на своём месте?

6. Что нужно запомнить

  • i идёт по первой последовательности, j по второй, каждый в одну сторону.
  • На каждом шаге хватает одного сравнения: меньшее из a[i] и b[j] самое маленькое из оставшихся.
  • Шагов n + m: для массивов из 4 и 5 чисел это 9 шагов.
  • Если запись идёт в тот же массив, проверьте, не затрёт ли она непрочитанное. Иногда надо идти с конца.

7. Как решать задачи этой главы

  1. Найдите в условии две последовательности: два массива или две строки. Спросите себя, отсортированы ли они.
  2. Решите, какой указатель двигать при каждом сравнении и что делать при равенстве.
  3. Решите, что делать, когда одна последовательность закончилась. Проверьте это на примере с пустым массивом.
