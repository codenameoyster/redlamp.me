Two Pointers по двум последовательностям: Merge, подсчёт и поиск общих значений. Считаем сравнения, записи и временные копии отдельно.

1. Задача: Merge двух Array

Даны два Array a и b, оба отсортированы по неубыванию. Соберите из них один отсортированный Array. Вызывать sort нельзя.

Пример: a = [1, 3, 5, 8], b = [2, 3, 6, 7, 9]. Ответ: [1, 2, 3, 3, 5, 6, 7, 8, 9].

Вход: n = len(a), m = len(b), вместе n + m чисел. Числа имеют ограниченный размер. Сравнение чисел и работа с индексом имеют постоянную цену в этой модели. Дополнительная память означает максимум одновременно нужных рабочих ячеек без входа и итогового ответа. Временные срезы входят в этот максимум.

2. Трассировка по шагам

Указатель i стоит на первом числе a, указатель j на первом числе b. На каждом шаге сравниваем a[i] и b[j], берём меньшее и сдвигаем его указатель.

Array a закончился. Остаток b это [9]. Он уже отсортирован и не меньше всего взятого, поэтому его дописываем целиком. На рисунке счётчики показывают работу, завершённую к данному состоянию; подпись объясняет следующий ход.

a = [1, 3, 5, 8]
b = [2, 3, 6, 7, 9]
i = j = 0
out = []
while i < len(a) and j < len(b):
    if a[i] <= b[j]:
        out.append(a[i])
        i += 1
    else:
        out.append(b[j])
        j += 1
out += a[i:] + b[j:]
print(out)

3. Инвариант и цена

Почему на каждом шаге хватает одного сравнения? a[i] это самое маленькое из оставшихся чисел a. b[j] это самое маленькое из оставшихся чисел b. Меньшее из них самое маленькое из всех оставшихся чисел.

Инвариант. Всё, что уже лежит в out, не больше всего, что осталось. Всё левее i и левее j уже обработано и больше не нужно.

Время: при непустых входах не больше n + m - 1 сравнений значений. В ответ записываются ровно n + m элементов. Добавление в Python list имеет постоянную амортизированную цену: редкие расширения распределяются по всем добавлениям. Копирование остатков тоже линейное. Итого O(n + m).

Дополнительная память: i и j занимают O(1), но a[i:] + b[j:] создаёт срезы и их объединение. Если осталось k элементов, одновременно нужны до 2k временных ячеек, поэтому здесь O(n + m) в худшем случае. Ответ out занимает ещё O(n + m). В примере k = 1: две временные ячейки для числа 9 и девять ячеек ответа.

Сравнение способов Merge

Можно дописать остатки циклом по индексам без срезов. Тогда время останется O(n + m), рабочее состояние станет O(1), а ответ по-прежнему займёт O(n + m). Объединение входов и Sorting имеет общую оценку O((n + m) log(n + m)) времени и O(n + m) рабочей памяти Python, кроме ответа. Python может использовать готовые упорядоченные участки. Merge сразу использует известный порядок.

4. Подсчёт с помощью Merge

Новая задача: для каждого b[j] посчитайте, сколько чисел в a строго меньше него. Оба Array отсортированы. Возьмите a = [1, 3, 5, 8] и b = [2, 3, 6]. Ответы: для 2 это 1, для 3 это 1, для 6 это 3.

Пока i < n и a[i] < b[j], увеличивайте i. Затем запишите i и переходите к следующему b[j]. При равенстве i не двигается: 3 не меньше 3. Для следующего запроса i не нужно возвращать назад.

Время: n = len(a), m = len(b). Не больше n успешных сравнений с продвижением i и m неуспешных сравнений перед ответами: O(n + m). Проверки границ тоже дают O(n + m). Дополнительная память: O(1), если записывать каждый ответ сразу без временных срезов или list. Вход занимает O(n + m), собранный ответ занимает O(m).

Когда выбрать Binary Search

Brute Force проверяет n чисел для каждого из m запросов: O(nm), здесь 12 сравнений. Binary Search для каждого b[j] ищет первую позицию со значением не меньше запроса: O(m log(n + 1)) времени, O(1) рабочей памяти и O(m) ответа. Он удобен, если запросов мало или они не отсортированы. Если a тоже не отсортирован, сначала учтите Sorting: O(n log n) времени и O(n) рабочей памяти Python. Для общего прохода по неупорядоченным запросам Sorting пар (значение, исходный индекс) добавит O(m log m) времени и O(m) памяти.

5. Практика: LeetCode 88

Merge Sorted Array. Здесь имена размеров заданы условием: m чисел в nums1 и n чисел в nums2. Оба участка отсортированы. Array nums1 имеет ещё n свободных ячеек справа. Выполните Merge в nums1 на месте, возвращать ничего не надо.

Если выполнять Merge слева направо, как в трассировке, запись может затереть числа nums1, которые вы ещё не прочитали. Как этого избежать без второго Array?

Подсказка 1

Свободное место лежит справа. С какого числа тогда начинать: с самого маленького или с самого большого?

Подсказка 2

Три указателя: i = m - 1 читает nums1, j = n - 1 читает nums2, write = m + n - 1 пишет. Все трое идут влево.

Подсказка 3

Когда можно остановиться: когда закончился nums1 или когда закончился nums2? Что в этот момент уже лежит на своём месте?

Подсказка 4: скелет
i, j, write = m - 1, n - 1, m + n - 1
while j >= 0:
    # в nums1 ещё есть числа и nums1[i] больше nums2[j]: ставим nums1[i]
    # иначе: ставим nums2[j]
    ...
    write -= 1

Решили? Докажите, что write никогда не затрёт непрочитанное число из nums1. Подсказка: как связаны write, i и j?

Время: не больше m + n записей, по одной на уменьшение write: O(m + n). Когда j < 0, оставшийся префикс nums1 уже готов. При n = 0 работа O(1). Дополнительная память: O(1) для трёх индексов. Вход занимает O(m + n); ответ использует готовые ячейки nums1. Прямой Merge с отдельным ответом требует ещё O(m + n) ячеек.

6. Что нужно запомнить

  • i идёт по первой последовательности, j по второй, каждый в одну сторону.
  • На каждом шаге хватает одного сравнения: меньшее из a[i] и b[j] самое маленькое из оставшихся.
  • Различайте сдвиги, сравнения и записи: в прямом Merge из примера это 8, 8 и 9.
  • Если запись идёт в тот же Array, проверьте, не затрёт ли она непрочитанное. Иногда надо идти с конца.

7. Как решать задачи этой главы

Is Subsequence

n = len(s), m = len(t). Ищите символ s[i] в t, двигая j всегда, а i только при совпадении. После i = n ответ уже True. Для пустой s ответ сразу True. Время: до m сравнений символов, O(m); чтение обеих String из внешнего входа отдельно стоит O(n + m). Дополнительная память: O(1); вход O(n + m), ответ bool O(1).

Много запросов Subsequence к одной t

Сохраните позиции каждой буквы t за O(m) времени и дополнительной памяти. Для очередной буквы s через Binary Search найдите первую позицию после предыдущей. Один запрос длины n займёт O(n log(m + 1)), без повторного прохода по всей t. Для q запросов длины n итог O(m + qn log(m + 1)), а повторные Two Pointers дают O(qm). Если хранить все ответы bool, нужно отдельно O(q) ячеек. Это сравнение для фиксированного алфавита строчных английских букв. Полная таблица Longest Common Subsequence требует O(nm) времени и ячеек и для одной такой проверки не нужна.

Merge Strings Alternately

n и m - длины word1 и word2. Добавляйте символы по очереди в Python list, затем вызовите "".join(out). Время: n + m добавлений и копирование n + m символов в String: O(n + m). Дополнительная память: O(n + m) для list. Итоговая String занимает отдельно O(n + m); во время join обе структуры существуют вместе. Входные String занимают O(n + m).

Почему не оценивать повторное сложение String как O(1)

String неизменяема. Модель копирования растущего результата при каждом out = out + char даёт 1 + 2 + ... + (n + m) копирований символов: O((n + m)²). Для шести символов это 21. Оптимизации конкретного Python не дают общей гарантии. Один join делает цену построения ответа явной. Срез оставшегося слова тоже создаёт копию.

Intersection of Two Arrays

n и m - длины nums1 и nums2. После Sorting двигайте указатель у меньшего значения; при равенстве двигайте оба. Для уникальности сравнивайте найденное число только с последним записанным. Время: O(n log n + m log m + n + m), обычно пишут O(n log n + m log m). Дополнительная память: O(n + m) для копий или рабочего места Sorting в Python; сам проход O(1). Вход O(n + m), ответ O(k), где k ≤ min(n, m) - число разных общих значений.

Если сначала проверять <, затем >, эти четыре итерации требуют шесть сравнений значений. Второе совпадение требует ещё одно сравнение с последним ответом, чтобы не записать повтор.

Другие способы найти пересечение

Проверка x not in out ищет по всему ответу и может сделать проход квадратичным. Hash Table через Python set даёт ожидаемое O(n + m) время и O(n + m) рабочую память; длинные цепочки совпавших хешей ухудшают оценку. При уже отсортированных входах Two Pointers дают O(n + m) время без Sorting. Brute Force проверяет nm пар, а удаление повторов требует отдельного учёта.
