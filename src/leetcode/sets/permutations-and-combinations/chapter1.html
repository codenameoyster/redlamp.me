Сначала научимся считать работу программы. Затем Product Rule, Sum Rule и Factorial помогут узнать число вариантов. Вычислить это число и построить все варианты требуют разной работы.

1. От операций к Big-O

Дан непустой Array a из n чисел. Найдём максимум через Linear Scan. Сначала best = a[0]. Затем для каждого индекса из range(1, n) сравним a[i] > best и при успехе обновим best. Копии Array здесь нет.

Время: ровно n − 1 сравнений значений и не больше n − 1 обновлений: O(n). При удвоении входа с 8 до 16 чисел сравнений становится 15 вместо 7. Это рост работы, а не измерение секунд.

Пройдите Array [3, 1, 4, 2] на рисунке. Счётчик увеличивается после каждого сравнения с best. Первое значение задаёт начальный максимум без сравнения.

Дополнительная память это максимум одновременно нужной рабочей памяти, без входа и готового ответа. Для Linear Scan вход занимает n ячеек, рабочие i и best занимают O(1), ответ занимает O(1). В других алгоритмах учитываем временные копии и Call Stack. Размер ответа указываем отдельно.

Пока считаем сравнение, сложение и умножение чисел ограниченного размера одной операцией. В Python большие int занимают больше битов, а операции с ними становятся дороже. Для больших счётчиков ниже считаем именно арифметические операции.

O(n) описывает класс границ, а n в таблице это одна функция. Например, проверок всех пар при n = 8 всего 28, а не 64.

Один поиск значения в неупорядоченном Array требует не больше n сравнений через Linear Scan: O(n) времени и O(1) рабочей памяти. Sorting только ради одного Binary Search требует O(n log n + log n) времени. Для максимума Sorting тоже делает лишнюю работу.

Если запросов q, отдельные Linear Scan требуют O(qn). Одна Sorting и q Binary Search требуют O(n log n + q log n); Python-копия через sorted занимает O(n) рабочей памяти. Hash Table строится один раз за ожидаемое O(n), затем q проверок дают ожидаемое O(q); всего O(n + q) времени и O(u) памяти для u разных значений. Здесь нужны ключи ограниченного размера и подходящее распределение хешей. Совпадения хешей могут увеличить время. Все методы возвращают q логических ответов; при сохранении это O(q) памяти ответа.

2. Product Rule

Есть a = 3 футболки и b = 4 пары штанов. К каждой футболке подходят все 4 пары: 3 · 4 = 12 нарядов. Из дома до школы 2 дороги, от школы до бассейна 3: 2 · 3 = 6 маршрутов.

Product Rule. Если первый выбор имеет a вариантов, а после каждого из них второй имеет b вариантов, пар будет a · b.

shirts = 3
trousers = 4
print(shirts * trousers)  # 12

Время: при известных a и b каждое из этих вычислений делает одно умножение: O(1) в модели ограниченных чисел. Дополнительная память: O(1), ответ тоже одно число. Построить все a · b пары требует O(ab) времени и O(ab) ячеек ответа; два индекса для такого перечисления занимают O(1).

Пароли: число вариантов и число записанных символов

У десятичного пароля длины d на каждой позиции 10 вариантов, включая 0. Ответ равен 10d. Цикл с начальным счётчиком 1 и умножением на 10 на каждой позиции делает d умножений: O(d) арифметических операций и O(1) целых переменных. Счётчик и ответ требуют O(d) битов.

3. Sum Rule

До школы идут a = 3 автобуса и b = 2 трамвая. Вы выбираете один транспорт: 3 + 2 = 5 способов.

Sum Rule. Если выбирают один вариант из a или один из b, а группы не пересекаются, всего a + b вариантов. Product Rule нужен для последовательных выборов; Sum Rule нужен для непересекающихся случаев.

Время: одно сложение известных a и b, O(1). Дополнительная память: O(1), ответ одно число. Если нужны сами варианты, запись a + b элементов требует O(a + b) времени и столько же памяти ответа. Для последовательной записи достаточно O(1) рабочей памяти.

4. Permutations и Factorial

Порядок 4 разных книг выбираем по позициям: 4 варианта, затем 3, затем 2 и 1. Product Rule даёт 4 · 3 · 2 · 1 = 24. Такие порядки называются Permutations. Их число равно Factorial: n! = 1 · 2 · ... · n; 0! = 1.

def factorial(n):
    result = 1
    for i in range(1, n + 1):
        result = result * i
    return result
print(factorial(5))  # 120

При неограниченном n произведение требует O(n log(n + 1)) битов, как и ответ; умножение уже не стоит O(1). Построение всех Permutations требует записать n · n! элементов. Backtracking для этого использует O(n) рабочей памяти и O(n · n!) времени и памяти ответа при n ≥ 1.

5. Выбор k из n по порядку

В забеге n = 8 бегунов и k = 3 разные медали. Золото может получить любой из 8, серебро любой из 7 оставшихся, бронзу любой из 6: 8 · 7 · 6 = 336. Порядок важен. Для кода из 3 разных цифр аналогично 10 · 9 · 8 = 720.

Время: каждое записанное произведение из трёх чисел содержит 2 умножения. Общий цикл от result = 1 умножает на n, n − 1, ..., n − k + 1: k умножений, O(k) арифметических операций. Дополнительная память: O(1) целых переменных, ответ одно число. Для R = n!/(n − k)! готовых порядков нужно kR элементов ответа, O(kR) времени и O(k) рабочей памяти Backtracking. Здесь 1 ≤ k ≤ n; для больших чисел стоимость битов учитываем отдельно.

6. Combinations: порядок не важен

Из n = 5 друзей выбираем команду из k = 2. По порядку есть 5 · 4 = 20 пар, но каждую команду посчитали 2! раз: 20 / 2 = 10. При k = 3 получаем 5 · 4 · 3 / 3! = 60 / 6 = 10. Это Combinations, их число обозначают C(n, k).

Каждая команда из k человек имеет k! порядков. Поэтому C(n, k) = n! / (k! · (n − k)!). Выбрать k человек равносильно выбору n − k оставшихся: C(n, k) = C(n, n − k).

from math import comb
print(comb(5, 2))  # 10
print(comb(10, 3), comb(10, 7))  # 120 120

Один вызов math.comb или math.factorial не означает O(1): работа выполняется внутри функции. Чтобы оценить понятный алгоритм для C(n, k), возьмём r = min(k, n − k), начнём с c = 1 и для i от 1 до r выполним c = c * (n - r + i) // i. Каждое деление здесь точное.

Время: r умножений и r целочисленных делений, O(r + 1) арифметических операций с учётом r = 0. Для C(5, 2) и C(5, 3) по 2 итерации; для C(10, 3) и C(10, 7) по 3. Дополнительная память: O(1) целых переменных; размер больших чисел растёт. Сам ответ C(n, k) занимает O(n + 1) битов, поскольку C(n, k) ≤ 2n.

Сравнение с Dynamic Programming

Pascal's Triangle использует C(n, k) = C(n − 1, k − 1) + C(n − 1, k). Dynamic Programming обновляет одну строку справа налево: O(nr) сложений и O(r + 1) хранимых чисел для r ≥ 1. Для r = 0 сразу возвращаем 1. Это удобно для многих промежуточных значений; формула с r итерациями подходит для одного ответа. Битовая стоимость больших чисел нужна в обоих случаях.

7. Subsets

Для каждого из n предметов есть два решения: взять или нет. По Product Rule получаем 2n вариантов, включая пустой. Это Subsets. Для яблока, груши и сливы вариантов 8; для 4 предметов 16, для 10 предметов 1024.

Время подсчёта: начиная с 1, умножаем на 2 n раз: O(n) арифметических операций. Дополнительная память: O(1) целых переменных, но счётчик и ответ требуют O(n + 1) битов. Сами Subsets содержат n · 2n − 1 элементов при n ≥ 1: каждый предмет входит в половину вариантов. Для n = 3 это 12 элементов в 8 ответах. Их построение занимает O(n · 2n) времени и памяти ответа, рабочий путь Backtracking занимает O(n).

8. Что нужно запомнить

  • Product Rule считает последовательные выборы, Sum Rule складывает непересекающиеся случаи.
  • Permutations: n!. Combinations: C(n, k). Subsets: 2n.
  • Число ответов, число операций и размер ответа могут различаться.
  • Big-O требует указать вход, операции и случай. Рабочую память считаем отдельно от входа и ответа.

9. Как решать задачи этой главы

  1. Решите маленький пример на бумаге.
  2. Определите, нужен один счётчик или сами варианты.
  3. Укажите размер входа и посчитайте проходы, арифметические операции и копии.
  4. Проверьте время и память выбранного способа по заметке к задаче.
