Next Permutation находит следующий вариант. Dynamic Programming считает пути. Блоки Factorial дают вариант с нужным номером. В конце сравним поиск N-Queens и запись всех ответов.

Дополнительная память означает максимум рабочих данных без входа и готового ответа. Считаем копии Python, буферы Sorting и Call Stack. Числа в ограничениях задач небольшие. Для больших Factorial и чисел путей считаем арифметические операции отдельно от стоимости их растущих битов.

1. Lexicographic Order

Запишите все Permutations чисел 1, 2, 3 так, как слова стоят в словаре. Сначала сравниваем первую цифру. Если она равна, сравниваем вторую. И так далее.

123  132  213  231  312  321

Это Lexicographic Order. В нём каждый вариант имеет номер: 123 первый, 132 второй, 321 шестой. Правило работает и для букв.

Проверьте себя: что идёт после 1 3 2? Ответ: 2 1 3.

Для двух Array длины n сравнение смотрит до n позиций: O(n) времени и O(1) рабочей памяти, результат сравнения имеет постоянный размер. Для 123 и 132 достаточно 2 позиций. Backtracking всех Permutations разных чисел с общим путём требует O(n·n!) времени, O(n) рабочей памяти и n·n! элементов ответа: при n = 3 это 18, при n = 4 уже 96. Поэтому получение одного следующего варианта не должно строить весь ответ из n! объектов.

2. Next Permutation

LeetCode 31. Дан Array. Нужен следующий вариант в Lexicographic Order. Сделаем три шага на примере 1 2 5 4 3.

  1. Идите справа налево. Найдите первое число, которое меньше своего правого соседа. Хвост 5 4 3 убывает, а 2 < 5. Это число 2.
  2. Справа от 2 найдите самое правое число, которое больше 2. Это 3. Поменяйте их местами: 1 3 5 4 2.
  3. Хвост после 3 стоит по убыванию: 5 4 2. Переверните его: 1 3 2 4 5.

Хвост 5 4 3 уже самый большой из возможных. Число перед хвостом заменяем на самое маленькое большее число справа. Потом разворачиваем невозрастающий хвост, чтобы получить минимальное продолжение. Равные числа также допустимы.

Если на шаге 1 ничего не нашлось, как в 3 2 1, это последний вариант. Разверните весь Array: 1 2 3.

def next_permutation(a):
    i = len(a) - 2
    while i >= 0 and a[i] >= a[i + 1]:
        i -= 1
    if i >= 0:
        j = len(a) - 1
        while a[j] <= a[i]:
            j -= 1
        a[i], a[j] = a[j], a[i]
    # При i == -1 разворачиваем весь Array
    a[i + 1:] = a[i + 1:][::-1]

a = [1, 2, 5, 4, 3]
next_permutation(a)
print(a)

Время: n - длина Array, s - длина хвоста. Поиск i проверяет до n − 1 соседних пар, поиск j до s значений. Разворот и запись хвоста требуют O(s). Итого O(n) в худшем случае. Дополнительная память: O(n) в этом коде: a[i + 1:] и [::-1] создают две временные копии длины s. Ответ записан во входной Array.

Замените присваивание со срезами на обмены через два индекса: левый от i + 1, правый от n − 1. После обмена сдвигайте их к центру. Это ⌊s/2⌋ обменов и O(1) рабочей памяти при том же O(n) времени. Sorting хвоста также даёт минимальное продолжение, но имеет общую верхнюю оценку O(n log n) и O(n) рабочего места Python. Невозрастающий хвост уже позволяет линейный разворот.

3. Пути в сетке

LeetCode 62. Сетка из 2 строк и 3 столбцов. Робот стоит в левом верхнем углу и идёт в правый нижний. Ходить можно только вправо (R) или вниз (D). Сколько есть путей?

Каждый путь это String из букв. Вправо нужно 2 шага, вниз 1 шаг. Всего 3 шага. Пути: RRD, RDR, DRR. Их 3.

Путь задаёт место буквы D. Выбираем 1 место из 3 без порядка: Combinations из главы 1 дают C(3, 1) = 3.

Для сетки из m строк и n столбцов: шагов вниз m − 1, шагов вправо n − 1, всего m + n − 2. Ответ C(m + n − 2, m − 1). Сетка 3 на 3: C(4, 2) = 6.

Dynamic Programming: число путей в клетку равно сумме значений сверху и слева. В первой строке и первом столбце по 1 пути.

Клетка в 3-й строке и 3-м столбце даёт 6. Код хранит только одну строку таблицы. Перед обновлением row[j] содержит значение сверху, а row[j - 1] уже содержит новое значение слева.

def unique_paths(m, n):
    row = [1] * n
    for _ in range(m - 1):
        for j in range(1, n):
            row[j] += row[j - 1]
    return row[-1]

print(unique_paths(3, 3))

Время: m - число строк сетки, n - число столбцов. Инициализация n ячеек, m − 1 проходов внешнего цикла и (m − 1)(n − 1) сложений дают O(mn). Дополнительная память: O(n) чисел в row; ответ - одно число. Если выбрать более короткое измерение для row, память станет O(min(m, n)).

Полная таблица требует O(mn) времени и памяти. Для одного числа достаточно строки. Формула C(m + n − 2, m − 1) с накоплением произведения требует t = min(m − 1, n − 1) арифметических шагов и O(1) рабочих целых чисел. Для 3 × 3: 3/1, затем 3·4/2 = 6, всего 2 шага. math.comb вычисляет тот же результат, но один вызов не означает O(1) времени. При неограниченной сетке сами числа растут в битах. Для 3 × 3 это 6 путей и 24 символа, а Dynamic Programming хранит лишь 3 счётчика.

4. Permutation Sequence: вариант с номером k

LeetCode 60. При n = 3, k = 3 нужен третий вариант в Lexicographic Order: 213. Получим его без перечисления всех Permutations.

Permutations идут блоками по первой цифре. С цифрой 1: 123, 132. С цифрой 2: 213, 231. С цифрой 3: 312, 321. В каждом блоке (n − 1)! = 2! = 2 варианта.

Нумеруем с нуля: k − 1 = 2. Номер блока: 2 // 2 = 1. Доступные цифры 1, 2, 3, берём цифру с номером 1, это 2. Остаток 2 % 2 = 0. Остались цифры 1, 3, размер блока теперь 1! = 1. 0 // 1 = 0, берём 1. Осталась 3. Ответ 213.

Для n = 4 размер блока 3! = 6. При k = 9: (9 − 1) // 6 = 1, первая цифра 2. Остаток 8 % 6 = 2, доступны 1, 3, 4. Следующий блок 2! = 2: 2 // 2 = 1, берём 3. Остаток 0: берём 1, потом 4. Ответ 2314.

from math import factorial
def kth_permutation(n, k):
    digits = list(range(1, n + 1))
    k -= 1
    out = ''
    for size in range(n - 1, -1, -1):
        block = factorial(size)
        out += str(digits.pop(k // block))
        k %= block
    return out

print(kth_permutation(4, 9))

Время: n - число цифр, k - номер с 1, F(s) - стоимость вызова factorial(s). Код делает n вызовов Factorial, до n(n − 1)/2 сдвигов при pop и до O(n²) копирования при росте String. Оценка: O(n²) + Σ F(s), s = 0…n − 1. Дополнительная память: O(n) для digits и промежуточного String. Ответ занимает n символов при ограничении n ≤ 9.

Почему один цикл не означает O(n)

Для n = 3, k = 3 нужны 3 вызова Factorial и 2 сдвига; для n = 4, k = 9 нужны 4 вызова и 4 сдвига. При k = 1 удаление первого элемента даёт максимум: 6 сдвигов при n = 4. Можно заранее вычислить Factorial за O(n) умножений и O(n) сохранённых чисел. Либо вычислить (n − 1)! один раз и уменьшать размер блока делением. Но удаление из середины Array всё равно оставляет O(n²) сдвигов в худшем случае. Общий буфер символов с одним join убирает повторное копирование String. Повторять Next Permutation до номера k проще, но это O(kn) времени и O(n) рабочей памяти для Array цифр, плюс n символов ответа. Сам переход с обменами требует O(1) памяти. В задаче n ≤ 9, поэтому текущий простой выбор по индексам подходит.

5. N-Queens: задача-вызов

LeetCode 51. Доска n на n. Поставьте n ферзей так, чтобы никакие два не били друг друга. Ферзь бьёт по строке, по столбцу и по двум диагоналям.

Ставим по одному ферзю в строку: сначала в строку 0, потом в строку 1. Это Backtracking: выбрать столбец, пойти глубже, отменить.

Клетка имеет координаты (r, c). Python set использует Hash Table: cols хранит столбцы, diag1 разности r − c, diag2 суммы r + c. Клетки (0, 1), (1, 2), (2, 3) имеют одну диагональ r − c = −1. Клетки (0, 3), (1, 2), (2, 1) имеют другую диагональ r + c = 3.

Pruning останавливает ветку, если столбец или диагональ заняты. Для n = 4 есть 2 ответа, для n = 8 их 92.

def solve_n_queens(n):
    cols, diag1, diag2, result = set(), set(), set(), []
    def place(r, board):
        if r == n:
            result.append(board[:])
            return
        for c in range(n):
            if c in cols or r - c in diag1 or r + c in diag2:
                continue
            cols.add(c)
            diag1.add(r - c)
            diag2.add(r + c)
            board.append(c)
            place(r + 1, board)
            board.pop()
            cols.remove(c)
            diag1.remove(r - c)
            diag2.remove(r + c)
    place(0, [])
    return result  # Номер столбца ферзя для каждой строки доски

print(solve_n_queens(4))

Время: n - размер доски, V - число посещённых неполных расстановок, Q - число решений. Цикл проверяет nV столбцов, копирование ответов пишет nQ чисел: O(nV + nQ) в среднем при O(1) операциях Hash Table. Дополнительная память: O(n) для трёх set, пути и Call Stack. Образец возвращает номера столбцов: O(nQ) памяти ответа.

LeetCode ждёт доски из String с точками и Q. На каждую из Q досок нужно n String по n символов: O(n²Q) времени построения и памяти ответа. Почему проверяем конфликт до полной доски

Brute Force по n столбцам в каждой из n строк даёт nⁿ расстановок. Проверка всех пар ферзей в каждой требует O(n²nⁿ) времени, O(n) рабочей памяти и ту же память правильных ответов. При n = 4 это 256 полных кандидатов. Текущий Backtracking посещает всего 17 состояний, включая корень и 2 готовых ответа. Поэтому число проверенных столбцов 60 не равно числу вызовов 17.

6. Что нужно запомнить

  • Lexicographic Order: сравниваем позиции до первого отличия.
  • Next Permutation: найти i, обменять, развернуть хвост. Срезы Python требуют O(n) памяти.
  • Unique Paths: Combinations или Dynamic Programming. Одна строка хранит n чисел.
  • Permutation Sequence: блоки по (n − 1)!. Учитывайте Factorial и сдвиги при удалении.
  • N-Queens: три Hash Table для конфликтов. Формат досок требует больше памяти, чем номера столбцов.
