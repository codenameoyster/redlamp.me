10 Order and counting without a list

  • Math
  • Two pointers
  • Combinatorics

Some tasks ask for one permutation, or only for a count. Use the order of the permutations, or a formula. For Next Permutation (up to 100 items) and Unique Paths, a list of all answers is too slow. For Permutation Sequence, the block method needs only n steps in place of n! steps.

Lexicographic order

Compare two lists item by item, as you compare words in a dictionary. The first different item decides the order. The permutations of [1, 2, 3] in this order are 123, 132, 213, 231, 312 and 321.

Next permutation

  1. From the right, find the first index i with nums[i] < nums[i + 1]. This is the pivot.
  2. From the right, find the first value that is larger than nums[i]. The part after the pivot is in decreasing order, so this is the smallest value in the part that is larger than the pivot. Swap the two values.
  3. Reverse the part after index i.

Worked example: [1, 3, 5, 4, 2]

StepActionList
1From the right, 3 < 5 is the first increase. The pivot is 3 at index 1.[1, 3, 5, 4, 2]
2From the right, 4 is the first value larger than 3. Swap 3 and 4.[1, 4, 5, 3, 2]
3Reverse the part after index 1: [5, 3, 2] becomes [2, 3, 5].[1, 4, 2, 3, 5]

Why reverse? The part after the pivot is in decreasing order. This is the last order of these items. After the swap, the part is still in decreasing order. The reverse makes it increasing, and that is the first order.

If no pivot exists, the list is the last permutation. Reverse all of it to get the first permutation.

LeetCode checks nums after your function returns. Change nums in place, for example with nums[i + 1:] = reversed(nums[i + 1:]). Do not assign a new list to nums.

The k-th permutation

The permutations of n digits come in n blocks of (n - 1)! permutations. All permutations in one block start with the same digit. So (k - 1) // (n - 1)! gives the index of the first digit. Then repeat with the remainder and the digits that are left.

Worked example: n = 4, k = 9

Count from 0, so the start index is k - 1 = 8.

[1, 2, 3, 4]83! = 6122

The answer is "2314".

Each cell in the top row and in the left column has 1 path. Each other cell is the sum of the cell above it and the cell to its left.

11 Complexity

  • Complexity
  • Recursion

A search that lists all answers cannot be faster than the size of its output. Each saved answer is a copy of a path, and the copy of a path with length n costs O(n).

ProblemAnswersTime
Permutationsn!O(n × n!)
Subsets2nO(n × 2n)
CombinationsC(n, k)O(k × C(n, k)) with the prune from section 9
Letter Combinations of a Phone Numberup to 4nO(n × 4n)
  • The permutation tree has fewer than e × n! nodes. e is a math constant, about 2.718. For n = 3 the tree has 16 nodes, and e × 3! is about 16.3.
  • The extra space is O(n) for the path and the recursion depth. This does not include the output.
  • Each recursive call uses one frame on the call stack. So a search with depth n uses O(n) stack space, not O(1).
  • The default recursion limit in Python is 1000. All tasks in this set stay far below it.
import sys
from math import factorial

print(factorial(12), 2 ** 12)
print(sys.getrecursionlimit())
479001600 4096
1000

In your explanation, write the time as the number of calls × the work in one call. When every leaf is an answer, the time is about the number of answers × the cost to copy one answer. In Combination Sum and N-Queens, most calls give no answer. For these searches, use an upper bound for the number of calls. For example, row r in N-Queens has at most n - r free columns, so N-Queens makes O(n!) calls. In Combination Sum, the depth is at most target / min(candidates) and each call has at most n children. So it makes at most O(ntarget / min(candidates) + 1) calls. Write the extra space as the depth of the tree.

Self-check

1,140. C(20, 3) = 20 × 19 × 18 / 3! = 1,140. Yes, a full search is fast enough.

Find the bug

This Combination Sum code raises RecursionError for [2, 3, 6, 7] and target 7. Find the place where a line is missing.

def backtrack(start, remain):
    if remain == 0:
        res.append(path[:])
        return
        
    for i in range(start, len(candidates)):
        path.append(candidates[i])
        backtrack(i, remain - candidates[i])
        path.pop()

The code has no stop before the loop. When remain is less than 0, the loop still adds values and calls backtrack again. The recursion goes deeper until Python raises RecursionError. Add if remain < 0: return before the loop. Another fix: sort the input. Then add if candidates[i] > remain: break in the loop.

13 Final self-check

The answers stay hidden until you push "Show answer". For a number question, type the number. Then push "Check". The page does not record a score.

Question 1

In how many ways can you put 4 books on a shelf?

4! = 24. The order matters and you use each book one time.

Question 2

5 runners compete for gold, silver and bronze. How many results are possible?

P(5, 3) = 5 × 4 × 3 = 60. The order matters, because gold and silver are different places.

Question 3

You choose 3 pizza toppings from 5. How many choices are possible?

C(5, 3) = 10. This is 60 / 3!, because the order of the toppings does not matter.

Question 4

A PIN has 4 digits. Each digit is from 0 to 9. How many PINs are possible?

104 = 10,000. The order matters and a digit can repeat.

Question 5

How many different words can you make from the letters of BOOK?

4! / 2! = 12. The two O letters can change places without a change to the word.

Question 6

A set has 5 items. How many subsets does it have? How many of them have 2 items?

25 = 32 subsets. C(5, 2) = 10 of them have 2 items.

Question 7: find the bug

This code lists the subsets of nums = [1, 2]. What does res contain at the end?

res, path = [], []
def backtrack(start):
    res.append(path)
    for i in range(start, len(nums)):
        path.append(nums[i])
        backtrack(i + 1)
        path.pop()
backtrack(0)

[[], [], [], []]. All 4 entries are the same list, and at the end it is empty. The fix is res.append(path[:]).

Question 8: find the bug

This code lists the subsets of nums = [1, 2, 3]. How many lists does res contain at the end?

res, path = [], []
def backtrack(start):
    res.append(path[:])
    for i in range(start, len(nums)):
        path.append(nums[i])
        backtrack(start + 1)
        path.pop()
backtrack(0)

16, not 8. The child starts after start, not after i. So lists such as [3, 2] and [3, 3] appear. The fix is backtrack(i + 1).

Question 9

Why does Subsets II use i > start and not i > 0 in the skip rule? Use the input [1, 1, 2].

i > 0 also blocks the second 1 as a child of the first 1. That is a deeper level, where the same value is allowed. So [1, 1] and [1, 1, 2] are missing.

Question 10

The input has 12 items. Can you list all permutations fast enough? Can you list all subsets fast enough?

Permutations: no. There are 12! = 479,001,600. Subsets: yes. There are only 212 = 4,096.

Question 11

Why does the prune in Combination Sum use break and not continue?

The input is sorted. When one value is larger than remain, all later values are larger too. So no later branch can give an answer.

Question 12 (extra)

You choose 3 scoops of ice cream from 4 flavours. A flavour can repeat and the order does not matter. How many choices are possible?

C(4 + 3 - 1, 3) = C(6, 3) = 20. This is the multiset rule from section 2.

14 How to use the tasks in this set

The set page lists the tasks in five stages. Do the stages in this order.

  • Warm-up One decision for each level of the tree. Count the results before you write code. Sections 2 to 4, and the take or skip code in section 7.
  • Core The four basic searches: permutations, combinations, subsets, and combinations with reuse. Sections 4 to 7. For Combination Sum and Combinations, also read the first two parts of section 9.
  • Duplicates and pruning Sort, skip equal values at one level, and stop branches that cannot give an answer. Sections 8 and 9.
  • Order and counting Find one permutation or a count without a list of all answers. Section 10.
  • Challenge Two hard tasks. They use sections 9 and 10.

Steps for each task

  1. Read the limits. Count the answers with a rule from section 2.
  2. Draw the tree for a small input.
  3. Write the state, the base case and the loop.
  4. Test the code on the small input. Compare the number of answers with your count from step 1.
  5. Write your explanation. Include the tree, the rule that removes duplicates or branches, and the time and space complexity.

Each task on the set page has a short note. If you cannot continue, read the note. Then read the sections for the stage of the task. The set page also has the reading links from the Tech Interview Handbook and Hello Interview.
