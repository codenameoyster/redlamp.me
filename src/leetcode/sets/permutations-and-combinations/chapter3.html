Backtracking строит варианты по частям. Sorting помогает убрать одинаковые ответы, а Pruning останавливает ветку, которая не даст ответа. Считаем вызовы, проверки и копии, а не только ответы.

Дополнительная память означает максимум одновременно нужных рабочих данных: Call Stack, временные копии и буферы. Вход и готовый ответ считаем отдельно. Операции с небольшими числами стоят O(1); добавление в конец Python list имеет амортизированную стоимость O(1).

1. Одинаковые ответы

Возьмите Array [1, 2, 2]. Шаблон Subsets из главы 2 без пропуска повторов даёт 8 результатов:

[], [1], [1, 2], [1, 2, 2], [1, 2], [2], [2, 2], [2]

[1, 2] и [2] встречаются по два раза. Две двойки имеют разные индексы, но одинаковое значение. Для Subsets II нужны только 6 разных результатов.

2. Sorting и пропуск на одном уровне

После Sorting одинаковые числа стоят рядом. На одном уровне Tree берите каждое значение один раз. Здесь уровень означает цикл for внутри одного вызова dfs.

nums.sort()    # Sorting до первого вызова
for i in range(start, len(nums)):
    if i > start and nums[i] == nums[i - 1]:
        continue    # на этом уровне такое число уже брали
    path.append(nums[i])
    dfs(i + 1, path)
    path.pop()

Почему i > start? В Array [1, 2, 2] после выбора [2] следующий вызов имеет start = 2. Там nums[2] == nums[1], но i == start. Это первая двойка на своём уровне. Она нужна для [2, 2].

В начале каждого вызова сохраните path[:]. Получатся [], [1], [1, 2], [1, 2, 2], [2], [2, 2].

Время: пусть n - длина Array, fᵢ - частота значения i, U = ∏(fᵢ + 1) - число ответов. Sorting и поиск требуют O(n log n + nU): каждый вызов проверяет до n индексов и копирует до n элементов. Дополнительная память: O(n) для пути, Call Stack и рабочего места Python Sorting. Ответ занимает O((n + 1)U): U контейнеров и nU/2 элементов.

3. Permutations с повторами

Array [1, 1, 2] даёт 6 позиционных Permutations, но разных только 3: [1, 1, 2], [1, 2, 1], [2, 1, 1]. Цикл всегда идёт с нуля, а Array used отмечает занятые индексы. Вторую единицу берём только после первой.

nums.sort()    # Sorting до первого вызова
for i in range(len(nums)):
    if used[i]:
        continue
    if i > 0 and nums[i] == nums[i - 1] and not used[i - 1]:
        continue    # такое же число слева ещё свободно
    used[i] = True
    path.append(nums[i])
    dfs(path)
    path.pop()
    used[i] = False

При длине пути n сохраняем path[:] и выходим до цикла. Пусть fᵢ - частоты, U = n!/∏fᵢ! - число ответов, V - число вызовов с неполным путём. Время: O(n log n + nV + nU). Цикл проверяет ровно nV индексов, даже если большинство уже заняты. Дополнительная память: O(n) для used, пути, Call Stack и Sorting. Ответ: nU элементов и U контейнеров.

Для n равных чисел U = 1, но n уровней проверяют по n индексов: O(n²). Поэтому O(nU) не описывает этот код. Backtracking по частотам проверяет u разных значений на неполный путь: O(n log n + uV + nU), где u - число разных значений, память O(n + u). Ещё вариант: после Sorting применять Next Permutation из главы 4. Получение и запись U ответов требует O(nU) времени после Sorting; рабочая память с Python Sorting равна O(n). Память ответа остаётся O(nU).

4. Pruning: остановите ветку заранее

Задача Combination Sum: даны числа [2, 3, 6, 7] и цель 7. Нужны все наборы с суммой 7. Одно число можно брать много раз. Ответ: [2, 2, 3] и [7].

В отличие от Combinations, число можно взять снова: передаём start = i. Меньшие индексы не берём, поэтому [3, 2, 2] не повторит [2, 2, 3]. Все кандидаты положительны: остаток строго уменьшается. После Sorting число больше остатка означает, что все следующие тоже не подходят. Pruning использует break.

candidates = [2, 3, 6, 7]
result = []
candidates.sort()    # Sorting до первого вызова
def dfs(start, remain, path):
    if remain == 0:
        result.append(path[:])
        return
    for i in range(start, len(candidates)):
        if candidates[i] > remain:
            break    # все следующие числа тоже больше
        path.append(candidates[i])
        dfs(i, remain - candidates[i], path)
        path.pop()

dfs(0, 7, [])
print(result)

Время: m - число кандидатов, T - цель, d = ⌊T/min(candidates)⌋ - максимальная глубина. V - число вызовов, R - число ответов, S - сумма их длин. Получаем O(m log m + V + S): проход цикла создаёт вызов или один раз завершает цикл через break. Дополнительная память: O(m + d) с Sorting и Call Stack. Ответ занимает O(R + S).

Для сравнения без Pruning нужен выход if remain < 0: return. Простое удаление break из примера не даёт 28 вызовов: оно продолжает уменьшать отрицательный остаток без остановки. В завершённом варианте глубина до d + 1, память по-прежнему O(m + d).

Pruning по оставшейся вместимости в Combinations

Пусть выбираем k из n чисел. Код главы 2 без проверки вместимости посещает V = Σ C(n, j), j = 0…k, состояний: время O(V + kC(n, k)). Если после выбора не хватит чисел до длины k, ветку можно не создавать. Тогда время O(kC(n, k)). Оба способа требуют O(k) рабочей памяти и O(kC(n, k)) памяти ответа при k ≥ 1.

5. Скобки

Generate Parentheses: дано n пар скобок, нужны все правильные String. При n = 2 это (()) и ()(). При n = 3 ответов 5:

((())), (()()), (())(), ()(()), ()()()

String строим по символу. Открыть скобку можно, пока opened < n. Закрыть можно, пока closed < opened: каждой закрывающей нужна открытая перед ней.

n = 3
result = []
def dfs(s, opened, closed):
    if len(s) == 2 * n:
        result.append(s)
        return
    if opened < n:
        dfs(s + '(', opened + 1, closed)
    if closed < opened:
        dfs(s + ')', opened, closed + 1)

dfs('', 0, 0)
print(result)

Время: R - число правильных String длины 2n. Этот поиск посещает O(R) допустимых префиксов и копирует до 2n символов на переход: O(nR). Только запись ответа уже требует 2nR символов. Дополнительная память: O(n²), потому что вызовы в Call Stack удерживают разные String длины 0, 1, …, 2n. Их сумма n(2n + 1). Это память одновременно живых префиксов, а не всех когда-либо созданных String.

6. Backtracking для знаков

Codeforces 1097B. Стрелка кодового замка стоит на нуле. Даны n поворотов в градусах, например 10, 20, 30. Каждый поворот делаем по часовой стрелке или против. Нужно узнать, может ли стрелка вернуться на ноль.

Каждому повороту ставим плюс или минус. Как в Subsets, есть два выбора на позицию. При n = 3 получаем 8 вариантов, при n = 15 их 32768.

Полный оборот это 360 градусов. Стрелка на нуле, когда сумма делится на 360. Для 10, 20, 30: 10 + 20 − 30 = 0, ответ YES. Для 10, 10, 10 ни одна из 8 сумм не делится на 360, ответ NO.

a = [10, 20, 30]
n = len(a)
def dfs(i, total):
    if i == n:
        return total % 360 == 0
    return dfs(i + 1, total + a[i]) or dfs(i + 1, total - a[i])

print('YES' if dfs(0, 0) else 'NO')

Время: n - число поворотов. Без раннего успеха получаем 1 + 2 + … + 2ⁿ = 2ⁿ⁺¹ − 1 вызовов, то есть O(2ⁿ). Текущую сумму обновляем за O(1) на переход. Дополнительная память: O(n) для Call Stack, до n + 1 вызовов одновременно. Ответ YES/NO занимает O(1).

Другие способы для замка

Bitmask Enumeration с пересчётом каждой суммы читает n·2ⁿ углов: O(n2ⁿ) времени и O(1) рабочих чисел. Dynamic Programming хранит достижимые остатки по модулю 360. Для каждого угла проверяем до 360 остатков и два перехода: O(360n) времени, O(360) памяти для двух слоёв, до 720 ячеек. При большом n число остатков ограничивает работу; для n ≤ 15 Backtracking проще. Оба способа возвращают один ответ YES/NO.

7. Что нужно запомнить

  • Subsets и Combinations: после Sorting пропуск при i > start and nums[i] == nums[i - 1].
  • Permutations: пропуск, если такое же число слева ещё не использовано. Считайте и проверки занятых индексов.
  • Pruning: ветка не может дать ответ, остановите её до вызова. Для положительных кандидатов после Sorting подходит break.
  • Скобки: открыть, пока opened < n; закрыть, пока closed < opened.
  • Память Call Stack включает объекты, которые удерживают вызовы. Копии String могут дать O(n²) даже при глубине O(n).
