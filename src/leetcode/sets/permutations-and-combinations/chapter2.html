Backtracking строит сами варианты: выбрать, пойти глубже, отменить. Считаем вызовы, проверки и скопированные элементы. Размер ответа часто определяет большую часть работы.

1. Когда нужны сами варианты

У Array [1, 2, 3] есть 8 Subsets. LeetCode 78 просит вернуть их все: [[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]. Здесь 8 объектов list и 12 записанных элементов. Одного числа 8 недостаточно.

Дополнительная память это одновременно живые рабочие данные и Call Stack, без входа и готового ответа. Здесь копирование одного элемента, индекс и сравнение чисел ограниченного размера имеют постоянную стоимость. Python list.append имеет O(1) амортизированную стоимость: отдельное расширение дороже, но суммарная работа пропорциональна числу добавлений.

2. Tree вариантов

Для n = 3 чисел можно на каждом уровне решать «взять или нет». Получается Tree с 1 корнем, затем 2, 4 и 8 узлами. Листьев 8, но вызовов всего 1 + 2 + 4 + 8 = 15. Backtracking проходит одну ветку, возвращается и пробует следующую.

Для n чисел такое Tree содержит 2n + 1 − 1 узлов. Копирование ответов добавляет n · 2n − 1 элементов при n ≥ 1: O(n · 2n) времени и памяти ответа. Общий путь и Call Stack занимают O(n). Ниже используем другой Tree: сохраняем каждый узел и выбираем только индексы правее последнего.

3. Recursion и Call Stack

Recursion это вызов функцией самой себя. Каждый вызов хранит место возврата и локальное состояние в Call Stack. В функции dfs нужны условие остановки и продвижение к нему. Для пути длины n одновременно активны не больше n + 1 вызовов, хотя всего вызовов может быть гораздо больше.

4. Выбрать, пойти глубже, отменить

  1. path.append(x) добавляет элемент к общему пути.
  2. dfs(...) рассматривает продолжения.
  3. path.pop() возвращает путь в прежнее состояние.

На каждый переход приходится одно добавление и одно удаление с конца. Обе операции стоят O(1) амортизированно: отдельный вызов может изменить размер хранилища list за O(d), где d - длина пути. Сохранение path[:] длины d копирует d элементов: O(d) времени и d ячеек ответа. Если сохранить сам path, ответы будут ссылаться на один изменяемый list, который в конце станет пустым.

5. Subsets

LeetCode 78. Вход: n разных чисел. Индекс start разрешает брать только числа правее последнего выбранного. Поэтому [2, 1] не повторит [1, 2]. Каждый узел даёт ответ, включая корень.

def subsets(nums):
    res = []
    def dfs(start, path):
        res.append(path[:])
        for i in range(start, len(nums)):
            path.append(nums[i])
            dfs(i + 1, path)
            path.pop()
    dfs(0, [])
    return res

print(subsets([1, 2, 3]))

Сравнение с Bitmask Enumeration

Bitmask хранит решения в битах: бит i равен 1, если берём nums[i]. Можно пройти все 2n значений Bitmask и для каждого проверить n битов. Это n · 2n проверок, плюс запись ответов. Время остаётся O(n · 2n), рабочий буфер занимает O(n). Для n = 3 получаем 24 проверки битов и те же 12 элементов ответа. Bitmask не устраняет стоимость вывода.

6. Permutations

LeetCode 46. Вход: n разных чисел. Теперь порядок важен: [1, 2, 3] и [2, 1, 3] различаются. Цикл идёт с нуля, а used запрещает повторно брать занятый индекс.

def permute(nums):
    res = []
    used = [False] * len(nums)
    def dfs(path):
        if len(path) == len(nums):
            res.append(path[:])
            return
        for i in range(len(nums)):
            if used[i]:
                continue
            used[i] = True
            path.append(nums[i])
            dfs(path)
            path.pop()
            used[i] = False
    dfs([])
    return res

print(permute([1, 2, 3]))

Время: на глубине d есть n!/(n − d)! вызовов. Каждый вызов до глубины n проверяет все n индексов, даже занятые. Суммарно O(n · n!) проверок и ровно n · n! элементов копий: O(n · n!) времени при n ≥ 1. Для n = 4 ответов 24, элементов 96.

Дополнительная память: O(n) для used, общего пути и Call Stack. При n = 3 это 3 пометки, до 3 элементов пути и 4 вызовов одновременно. Ответ занимает O(n · n!). Отмена включает и path.pop(), и used[i] = False.

Сравнение с Next Permutation

После Sorting можно многократно применять Next Permutation. Каждый следующий порядок требует O(n) времени в худшем случае; копирование всех n! порядков всё равно даёт O(n · n!) времени и памяти ответа. Рабочий Array-копия занимает O(n), Call Stack для Recursion не нужен. Сам переход можно сделать индексами с O(1) рабочей памятью.

7. Combinations и Pruning

LeetCode 77. Вход: n чисел от 1 до n, длина ответа k, где 1 ≤ k ≤ n. Порядок не важен. Используем start, но сохраняем только пути длины k.

def combine(n, k):
    res = []
    def dfs(start, path):
        if len(path) == k:
            res.append(path[:])
            return
        for x in range(start, n + 1):
            path.append(x)
            dfs(x + 1, path)
            path.pop()
    dfs(1, [])
    return res

print(combine(4, 2))

При n = 4 и k = 2 получаем [[1, 2], [1, 3], [1, 4], [2, 3], [2, 4], [3, 4]]. Вызовов 1 + 4 + 6 = 11, ответов 6, копий элементов 12. Путь [4] тоже посещаем, хотя продолжить его нельзя.

Время текущего кода: V = C(n, 0) + C(n, 1) + ... + C(n, k) вызовов и V − 1 переходов, плюс k · C(n, k) элементов копий: O(V + k · C(n, k)). Дополнительная память: O(k) для пути и Call Stack; ответ занимает O(k · C(n, k)). Для k = n код посещает 2n узлов ради одного ответа.

Pruning по числу оставшихся мест

Нужно ещё need = k - len(path) чисел. После выбора x должно остаться хотя бы need − 1 чисел, то есть x <= n - need + 1. Для Pruning заменим только границу цикла на range(start, n - (k - len(path)) + 2). Правая граница range не включается.

8. String: буквы на телефоне и регистр

LeetCode 17. В String digits длины n каждая цифра выбирает букву своей кнопки. Для "23" это 3 · 3 = 9 String: ad, ae, af, bd, be, bf, cd, ce, cf. На каждом уровне выбираем букву, в листе соединяем общий путь через join.

KEYS = {'2': 'abc', '3': 'def', '4': 'ghi', '5': 'jkl',
        '6': 'mno', '7': 'pqrs', '8': 'tuv', '9': 'wxyz'}
def letters(digits):
    res = []
    def dfs(i, path):
        if i == len(digits):
            res.append(''.join(path))
            return
        for ch in KEYS[digits[i]]:
            path.append(ch)
            dfs(i + 1, path)
            path.pop()
    if digits:
        dfs(0, [])
    return res

print(letters('23'))

Время: для n ≥ 1 пусть R будет произведением числа букв всех кнопок, R ≤ 4n. Проход по Tree требует O(R) вызовов, а R операций join копируют по n символов: O(nR). Для "23" это 1 + 3 + 9 = 13 вызовов и 18 символов; для "234" это 40 вызовов и 81 символ.

Дополнительная память: O(n) для пути и Call Stack, таблица KEYS имеет постоянный размер. Ответ занимает O(nR) символов. При "23" путь хранит до 2 символов, Call Stack до 3 вызовов. Пустой вход в показанном коде даёт [] за O(1) времени и памяти.

Letter Case Permutation и способы хранения пути

LeetCode 784. Пусть n будет длиной String, а l числом английских букв. Буква даёт две ветки: строчная и заглавная. Цифра даёт одну. Ответов 2l, но каждый содержит все n символов, включая цифры.

Backtracking с общим list и join только в листе делает O(n · 2l) работы и сохраняет столько же символов ответа. Рабочая память O(n) для пути и Call Stack. У "a1b2" по уровням 1, 2, 2, 4, 4 вызова: всего 13; 4 ответа содержат 16 символов. При l = 0 остаются один ответ и O(n) работы.

Итеративное расширение всех префиксов хранит целый уровень: до O(n · 2l) рабочих символов. Создание новой String на каждом шаге Recursion удерживает префиксы длины 0, 1, ..., n: до O(n²) рабочих символов. Общий буфер сохраняет O(n), пока готовые ответы учитываем отдельно. Для телефона сравнение такое же, с R вместо 2l.

9. Что нужно запомнить

  • Subsets сохраняем в каждом узле; Permutations и Combinations только при нужной длине.
  • Считайте все вызовы и неудачные проверки, затем стоимость копий.
  • Pruning уменьшает лишние вызовы, но не размер нужного ответа.
  • Один общий путь занимает память по глубине, а не по общему числу вызовов.

10. Как решать задачи этой главы

  1. Проверьте, важен ли порядок и допустимы ли повторные элементы.
  2. Вычислите число ответов и сумму их длин для маленького входа.
  3. Выберите start или used, условие сохранения и отмену.
  4. Посчитайте вызовы, копии и максимальную длину пути отдельно.
