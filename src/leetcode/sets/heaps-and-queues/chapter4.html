В жадной задаче каждый шаг берёт лучшее из того, что доступно сейчас, а heap отдаёт это лучшее за O(log n).

1. Слияние k отсортированных списков

Даны три отсортированных списка: L0 = [1, 5, 9], L1 = [2, 3, 10], L2 = [4, 6, 7]. Наименьшее число стоит в начале одного из них. Кладём в heap первое число каждого списка. Потом много раз достаём наименьшее, пишем его в ответ и кладём следующее число того же списка, если оно есть.

В heap лежат кортежи (число, номер списка, позиция). Число стоит первым, поэтому heap сравнивает кортежи по числу. Номер списка и позиция говорят, откуда взять следующее число.

import heapq

lists = [[1, 5, 9], [2, 3, 10], [4, 6, 7]]
h = [(lst[0], i, 0) for i, lst in enumerate(lists) if lst]
heapq.heapify(h)
out = []
while h:
    v, i, j = heapq.heappop(h)
    out.append(v)
    if j + 1 < len(lists[i]):
        heapq.heappush(h, (lists[i][j + 1], i, j + 1))
print(out)   # [1, 2, 3, 4, 5, 6, 7, 9, 10]

Правило. В heap не больше k кортежей: по одному текущему числу от каждого списка. Каждое из N чисел один раз входит в heap и один раз выходит, поэтому время O(N log k).

Матрица в LeetCode 378 это n отсортированных строк. Слейте их и остановитесь на k-м числе.

2. Лучшее из того, что уже пришло

LeetCode 1834. Задачи (приход, длительность), номера с 0: [[1, 2], [2, 4], [3, 2], [4, 1], [20, 3]]. Процессор делает одну задачу за раз. Когда он свободен, он берёт самую короткую из пришедших задач, а при равной длительности задачу с меньшим номером.

Отсортируйте номера задач по времени прихода. Указатель идёт по ним и кладёт в heap (длительность, номер) каждой задачи, которая уже пришла. Процессор достаёт вершину, и время t растёт на её длительность.

В момент 10 heap пуст, а задача 4 придёт только в 20. Если прибавлять к t по 1, цикл сделает 10 лишних шагов, а при приходе в 109 около миллиарда. Лимит 2 с на пример, 3 с на скрытый тест.

Правило. Указатель кладёт в heap все пришедшие задачи. Если heap после этого пуст, сразу ставьте t равным времени прихода следующей задачи. Каждая задача один раз входит в heap и один раз выходит: время O(n log n).

3. Передумать: взять всё и выбросить худшее

Codeforces 1526C2. Зелья [4, −3, −1, −2, 2] стоят в ряд, и каждое меняет здоровье на своё число. Здоровье в начале 0 и никогда не должно стать меньше 0. Сколько зелий можно выпить?

Пьём каждое зелье и кладём его в heap на минимум. Если здоровье стало меньше 0, достаём из heap самое вредное из выпитых зелий и вычитаем его число из здоровья.

На зелье −2 здоровье стало −2. Без текущего −2 здоровье было бы 0, а без −3 оно равно 1. Выпитых зелий в обоих случаях 3, но здоровья больше без −3. Перебор всех 25 = 32 вариантов тоже даёт 4 зелья.

Правило. Выбрасываем худшее из взятых, а не обязательно текущее. Зелий выпито столько же, а здоровье не меньше. Одного выброса хватает: худшее зелье не лучше текущего, и здоровье снова не меньше 0.

4. Сортировка, потом heap размера k

LeetCode 2542. nums1 = [1, 3, 3, 2], nums2 = [2, 1, 3, 4], k = 3. Выберите k номеров. Счёт это сумма их nums1, умноженная на минимум их nums2. Нужен наибольший счёт.

Отсортируем пары (nums2, nums1) по nums2 от большего к меньшему: (4, 2), (3, 3), (2, 1), (1, 3). Кладём nums1 в heap на минимум и держим сумму heap. Если в heap больше k чисел, выбрасываем наименьшее. Если ровно k, считаем сумму, умноженную на текущее nums2.

  • (4, 2): heap [2], сумма 2.
  • (3, 3): heap [2, 3], сумма 5.
  • (2, 1): heap [1, 3, 2], сумма 6, счёт 6 · 2 = 12.
  • (1, 3): кладём 3 и выбрасываем 1, сумма 8, счёт 8 · 1 = 8.

Ответ 12. У пар до текущей nums2 не меньше текущего. Поэтому произведение никогда не больше настоящего счёта чисел из heap. А на последней по порядку паре лучшего выбора heap держит k самых больших nums1 из пройденных пар, и произведение не меньше счёта лучшего выбора.

Правило. Сортировка по nums2 даёт кандидата на минимум, а heap на минимум размера k даёт наибольшую сумму nums1 среди пройденных пар. Сумму держите числом: прибавляйте при heappush, вычитайте при heappop. Новый sum(h) на каждом шаге стоит O(k), и всё решение O(nk).

5. Два heap с двух концов

LeetCode 2462. costs = [5, 1, 8, 9, 7, 2, 6], candidates = 2, k = 3. Каждый раз нанимаем самого дешёвого из первых 2 и последних 2 работников, при равной цене с меньшим номером. Нанятый уходит из ряда.

Heap L держит цены первых candidates работников, heap R цены последних. Указатели l и r показывают, кого добавить следующим. Берём меньшую вершину, при равных ценах из L: номера в L меньше номеров в R. Если один heap пуст, берём из другого. Heap, из которого взяли, добирает одного работника со своего указателя.

Правило. Оба heap добирают работников, только пока l ≤ r. Тогда ни один работник не попадёт в оба heap. Если 2 · candidates ≥ n, все работники сразу лежат в двух heap, и R получает только тех, кто не попал в L.

6. Что нужно запомнить

  • В heap слияния кортеж (число, номер списка, позиция): по нему видно, откуда брать следующее число.
  • Heap пуст, а задачи ещё придут: перенесите время на следующий приход.
  • Выбрасываем худшее из взятых, а не обязательно текущее.
  • Сумму heap держите числом, а не считайте sum(h) заново.
  • Два heap с двух концов добирают работников, пока l ≤ r.

7. Как решать задачи этой главы

  1. Найдите, что доступно сейчас: текущие числа списков, пришедшие задачи, выпитые зелья, пройденные пары.
  2. Решите, что лежит в heap и что стоит первым в кортеже.
  3. Прогоните heap на примере из условия на бумаге: что лежит в нём после каждого шага.
  4. Посчитайте операции. Если каждый элемент один раз входит в heap и не больше одного раза выходит, операции с heap стоят O(n log n). Остальная работа должна быть не больше: без шагов времени по 1 и без sum(h) на каждом шаге.
