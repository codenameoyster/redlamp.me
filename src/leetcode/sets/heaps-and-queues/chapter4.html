Greedy выбирает лучшее из доступного сейчас. Heap даёт вершину за O(1), а удаление или добавление при размере h требует O(log(h + 1)) времени. Правильность выбора нужно доказать отдельно.

1. K-Way Merge

Вход: k отсортированных последовательностей, всего N чисел. Пример: L0 = [1, 5, 9], L1 = [2, 3, 10], L2 = [4, 6, 7], k = 3, N = 9. В Min-Heap кладём первое число каждой непустой последовательности. Достаём наименьшее, записываем в ответ и добавляем следующее из той же последовательности.

Запись (число, номер последовательности, позиция) задаёт приоритет и место следующего числа. Числа из ограничений и сравнения таких tuple считаем постоянной работой.

import heapq

lists = [[1, 5, 9], [2, 3, 10], [4, 6, 7]]
h = [(lst[0], i, 0) for i, lst in enumerate(lists) if lst]
heapq.heapify(h)
out = []
while h:
    v, i, j = heapq.heappop(h)
    out.append(v)
    if j + 1 < len(lists[i]):
        heapq.heappush(h, (lists[i][j + 1], i, j + 1))
print(out)   # [1, 2, 3, 4, 5, 6, 7, 9, 10]

Время: просмотр k последовательностей и Heapify стоят O(k). Затем N удалений и N − q добавлений, где q ≤ k - число непустых последовательностей. Итого O(k + N log(k + 1)) в худшем случае. В примере 3 начальные записи, один heapify, 9 heappop, 6 heappush и 9 записей ответа. Число вызовов Heap не равно числу сравнений внутри них.

Дополнительная память: O(k), здесь пик 3 tuple. Считаем максимум живых рабочих записей без входа и результата. Ответ отдельно: O(N), здесь 9 чисел. Если сразу передавать результат потребителю, например через heapq.merge, все N чисел хранить не нужно; вызов list(...) снова их накопит.

2. Single-Threaded CPU: только доступные задачи

Вход: n пар (приход, длительность), номера с 0. Пример [[1, 2], [2, 4], [3, 2], [4, 1], [20, 3]]. Sorting номеров по приходу позволяет добавлять в Min-Heap только пришедшие задачи. Ключ (длительность, номер) выбирает самую короткую, при равенстве - меньший номер. После выбора время t увеличивается на длительность.

Heap пуст в t = 10: сразу ставим t = 20. Это одно присваивание вместо 10 прибавлений по 1. Если начинать с t = 0, в примере есть ещё переход 0 → 1: всего 2 перехода вместо 11 пустых тактов. Число H пустых тактов не ограничено числом задач.

Время: Sorting и n добавлений с n удалениями дают O(n log(n + 1)) в худшем случае. Переходов к следующему приходу не больше n. Пошаговое ожидание добавило бы O(H). Дополнительная память: O(n) для порядка прихода, рабочего места Python Sorting и Heap. Здесь порядок содержит 5 номеров, пик Heap - 2 записи. Ответ отдельно: O(n), порядок [0, 2, 3, 1, 4] из 5 номеров.

Альтернатива: искать следующую задачу через Linear Scan по всем n при каждом выборе. Это O(n²) времени и O(n) флагов, здесь 5 · 5 = 25 проверок записей. Общий Sorting по длительности неверен: короткая задача может ещё не прийти.

3. Potions: взять и удалить худшее

Вход: n изменений здоровья, пример [4, −3, −1, −2, 2]. Здоровье начинается с 0 и всегда должно быть неотрицательным. Прибавляем очередное число, добавляем его в Min-Heap. Если здоровье стало отрицательным, удаляем наименьшее принятое число и вычитаем его из здоровья.

После −2 здоровье равно −2. Удаление −3 оставляет здоровье 1, удаление текущего −2 оставило бы 0. Число принятых зелий одинаковое. Удаление самого вредного сохраняет больше здоровья для будущих шагов. Одного удаления хватает: минимальное принятое число не больше текущего, а до текущего здоровье было неотрицательным.

Время: n heappush, не больше n heappop, O(n log(n + 1)) в худшем случае. Здесь 5 добавлений, 1 удаление и 6 изменений здоровья. Дополнительная память: O(n), пик 4 записи. Ответ отдельно: одно число 4, O(1). Brute Force проверяет 2ⁿ вариантов с проходом по n позициям: O(n · 2ⁿ) времени, O(n) рабочих флагов выбора. Здесь полный проход по 32 вариантам делает 160 проверок флагов; ранний отказ может сократить работу.

4. Maximum Subsequence Score: Sorting и сумма

Вход: неотрицательные Array nums1 и nums2 длины n; выбрать k номеров. Счёт = сумма выбранных nums1 · минимум выбранных nums2. Для nums1 = [1, 3, 3, 2], nums2 = [2, 1, 3, 4], k = 3 применяем Sorting пар (nums2, nums1) по убыванию nums2. Min-Heap хранит k наибольших nums1 среди пройденных пар. После вставки удаляем минимум, если размер превысил k.

Время: Sorting O(n log(n + 1)) плюс O(n log(k + 1)) для Heap, итого O(n log(n + 1)) в худшем случае. Здесь 4 добавления, 1 удаление, 5 изменений суммы и 2 произведения. Дополнительная память: O(n + k) = O(n) для пар, Python Sorting и Heap; в примере 4 пары, пик Heap 4 числа до удаления. Ответ отдельно: одно число, O(1).

Повторный sum и Brute Force

Вызов sum(h) только при полном Heap делает (n − k + 1)k посещений: здесь 2 · 3 = 6. В целом получается O(n log(n + 1) + nk), включая Sorting. Сохранённая сумма требует n прибавлений и n − k вычитаний. Brute Force выбирает C(n,k) наборов и считает каждый за O(k): O(k · C(n,k)) времени, O(k) рабочих индексов. Здесь 4 набора по 3 номера, 12 посещений. Ответ в обоих случаях - одно число.

5. Total Cost to Hire K Workers: доступ с двух концов

Вход: n цен, c = candidates, нанять k работников. Пример costs = [5, 1, 8, 9, 7, 2, 6], c = 2, k = 3. Min-Heap L содержит первых c доступных работников, R - последних c. Ключ (цена, исходный номер) сохраняет правило равенства. Берём меньшую вершину; при одинаковой цене номер из L меньше. Пустой Heap не участвует в выборе.

Сначала соберите h = min(n, 2c) разных кандидатов и вызовите heapify для каждой группы. Указатели l и r отмечают ещё не добавленную середину. После найма добавляем одного работника с той же стороны, только если l ≤ r. Так перекрытие групп не создаёт копий.

Время: построение O(h), k удалений и не больше k добавлений: O(h + k log(h + 1)) в худшем случае. Чтение n входных цен отдельно стоит O(n). Инициализация повторными heappush даёт O(h log(h + 1)) вместо O(h). В примере 4 начальные записи, 2 heapify, 3 heappop, 3 heappush и 3 сравнения вершин; сумма 8. Последнее пополнение показано в рисунке, хотя после последнего найма его можно пропустить.

Дополнительная память: O(h), пик двух Heap вместе 4 записи. Ответ отдельно: одна сумма, O(1). Linear Scan по доступным группам требует O(kh) времени и O(h) записей; здесь 3 выбора по 4 кандидата дают 12 посещений и 9 сравнений. Sorting всех работников по цене допустим только когда все сразу доступны, например при 2c ≥ n. В общем случае он нарушает правило доступности.

6. Что нужно запомнить

  • Heapify строит Heap за линейное время; повторные вставки имеют другую границу.
  • Размер Heap задаёт стоимость одной операции. Считайте и число операций, и живые записи.
  • Сумму обновляйте, время простоя пропускайте, доступность проверяйте.
