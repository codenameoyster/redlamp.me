Monotonic Queue находит максимум каждого Sliding Window за один проход. Реализация через Monotonic Deque хранит номера: каждый номер входит один раз и выходит не больше одного раза.

1. Максимум каждого Sliding Window

Вход: Array a = [2, 7, 3, 1, 5, 2, 6, 4] длины n = 8, размер окна k = 3, 1 ≤ k ≤ n. Ответ [7, 7, 5, 5, 6, 6]. Сравнения и арифметику чисел из ограничений считаем постоянной работой.

Brute Force читает каждое окно целиком. Для максимума берёт первое число и сравнивает с остальными k − 1. Всего n − k + 1 окон.

Brute Force: посещения элементов и сравнения значений

8, 366 · 3 = 186 · 2 = 12
100 000, 50 00050 0012 500 050 0002 499 999 999

Время: O((n − k + 1)k) для полного прохода. Дополнительная память: O(1) для максимума и индексов, если читать по номерам без срезов. Срез окна добавляет O(k) временных элементов. Ответ отдельно: n − k + 1 чисел, O(n − k + 1). Здесь и дальше считаем максимум одновременно хранимых рабочих записей без входа и ответа.

2. Heap с отложенным удалением

Min-Heap хранит пары (−x, i). Вершина даёт наибольшее x. Пока номер вершины ≤ i − k, удаляем вершину. На i = 4 пара (−7, 1) уже вне окна; после её удаления ответ 5. Старые пары ниже вершины остаются до своего выхода наверх.

Время: n вызовов heappush и не больше n вызовов heappop дают O(n log(n + 1)) в худшем случае. Дополнительная память: O(n), не O(k): на возрастающем входе старые меньшие числа остаются под вершиной. Ответ отдельно: O(n − k + 1). Удаление ссылок не обещает немедленного уменьшения памяти процесса.

Тот же вход n = 8, k = 3: разные единицы работы

3. Почему можно удалить кандидата

После i = 3 в Deque значения 7, 3, 1. Приходит 5. Числа 3 и 1 меньше и старше: пока они в окне, 5 тоже в окне. Поэтому они больше не нужны для максимума.

Правило. Пришло x: удалите сзади все значения y ≤ x. Значения оставшихся номеров строго убывают. Более новое равное число остаётся в окне дольше.

4. Monotonic Deque шаг за шагом

Храним номера, чтобы проверять срок каждого кандидата. На шаге i окно занимает номера i − k + 1..i. Удаляем меньшие или равные значения сзади, добавляем i, затем удаляем вышедший номер спереди. Начиная с i = k − 1 записываем a[dq[0]].

Время: ровно n добавлений и не больше n удалений. Граница 2n считает только эти вызовы методов, а не все инструкции. Успешное сравнение сзади удаляет номер, неуспешное завершает проход для текущего x. Таких сравнений тоже O(n); ещё есть n проверок срока и n − k + 1 записей ответа. Всё вместе O(n) в худшем случае, амортизированно O(1) на входной элемент.

Дополнительная память: O(k) номеров. После шага их не больше k; добавление перед проверкой срока может временно дать k + 1. В показанном входе пик 3. Ответ отдельно: O(n − k + 1), здесь 6 чисел.

5. Код и знак сравнения

from collections import deque

a = [2, 7, 3, 1, 5, 2, 6, 4]
k = 3
dq = deque()
res = []
for i, x in enumerate(a):
    while dq and a[dq[-1]] <= x:
        dq.pop()
    dq.append(i)
    if dq[0] <= i - k:
        dq.popleft()
    if i >= k - 1:
        res.append(a[dq[0]])
print(res)   # [7, 7, 5, 5, 6, 6]

Именно этот код делает 5 pop, 1 popleft и 10 сравнений a[dq[-1]] <= x. Проверки пустоты сюда не входят. Для минимума замените ≤ на ≥: доказательство времени и памяти такое же.

6. Два Monotonic Deque: max − min ≤ limit

LeetCode 1438: вход nums длины n и limit ≥ 0. Нужна длина самого длинного Subarray с max − min ≤ limit. Two Pointers двигают границы только вперёд; один Deque хранит максимум, другой минимум. При добавлении удаляем равные значения тоже.

Для [4, 8, 5, 6, 7, 1, 2], limit = 3 ответ 4: окно [8, 5, 6, 7]. При r = 5 число 1 вынуждает сдвинуть l с 1 до 5. Из начала Deque максимума уходят 8 и 7.

while nums[mx[0]] - nums[mn[0]] > limit:
    l += 1
    if mx[0] < l:
        mx.popleft()
    if mn[0] < l:
        mn.popleft()

Время: 2n добавлений, не больше 2n удалений и n сдвигов l за весь проход: O(n) в худшем случае. Несколько вложенных циклов дают эту оценку только потому, что суммарное движение ограничено. В примере 14 добавлений, 11 удалений и 5 сдвигов l; условие max − min проверено 12 раз. Дополнительная память: O(w), где w - наибольшая проверяемая ширина до сжатия; w ≤ n. Здесь пик двух Deque вместе 5 номеров. Ответ отдельно: одно число, O(1).

Сравнение способов для переменного окна

Новые max и min при каждом расширении или сжатии дают O(n²) времени в худшем случае: до O(n) посещений на каждое из O(n) состояний. Без срезов рабочая память O(1). Ordered Set с частотами даёт O(n log(n + 1)) времени и O(w) записей. Deque полезен, когда обе границы идут только вперёд.

8. Sliding Window с суммой: роботы

LeetCode 2398: вход chargeTimes и runningCosts длины n, положительные стоимости, бюджет budget. Цена окна длины k равна max(chargeTimes) + k · sum(runningCosts). Deque даёт максимум; сумму храните числом. При новом r прибавьте runningCosts[r], при сдвиге l вычтите runningCosts[l]. Пока l ≤ r и цена выше budget, сжимайте окно.

Для chargeTimes = [3, 6, 1, 3, 4], runningCosts = [2, 1, 3, 4, 5], budget = 25 ответ 3. Получаем 5 добавлений в Deque, 4 удаления, 8 изменений суммы (5 прибавлений и 3 вычитания) и 8 проверок цены. Пик Deque - 2 номера.

Время: O(n) в худшем случае. Каждая граница проходит вход один раз; Deque тоже делает O(n) работы. Положительные runningCosts гарантируют: расширение не уменьшает цену, сжатие не увеличивает её. Поэтому отвергнутую левую границу возвращать не нужно. Дополнительная память: O(w), где w - наибольшая проверяемая ширина до сжатия, в худшем случае O(n). Сумма и индексы занимают O(1). Ответ отдельно: одно число, O(1).

Почему важна сохранённая сумма

Повторный sum или max по окну добавляет до O(n²) работы: например, без сжатия sum посетит 1 + 2 + ... + n элементов. При n = 5 это 15 посещений против 5 прибавлений. Срезы ещё требуют O(w) временной памяти. Binary Search по длине с линейной проверкой даёт O(n log(n + 1)) времени и O(n) рабочей памяти в худшем случае. Для этого условия достаточно одного Sliding Window.

9. Что нужно запомнить

  • Monotonic Queue реализуем через Deque номеров. Сзади удаляем кандидатов, спереди истёкшие номера.
  • 2n - граница числа добавлений и удалений одного Deque, а не всех инструкций.
  • Рабочую память и размер ответа считаем отдельно. Heap с отложенным удалением может хранить весь вход.

10. Как решать задачи этой главы

  1. Определите входные размеры и правило допустимого окна.
  2. Докажите, почему удалённый кандидат больше не нужен.
  3. Посчитайте суммарные добавления, удаления и сдвиги границ.
  4. Проверьте пик живых записей, временные срезы и память ответа.
