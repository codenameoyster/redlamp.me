Queue отдаёт элементы в порядке прихода. Deque поддерживает оба конца. Стоимость одного вызова и стоимость всего процесса нужно считать отдельно.

Модель стоимости. n - число входных элементов. Числа ограничены по размеру: сравнение и арифметика стоят O(1). Считаем вызовы методов, сдвиги ссылок или продажи билетов, а не секунды работы Python. O(f(n)) ограничивает рост работы; ниже указан случай, к которому относится оценка.

Дополнительная память - наибольший объём одновременно нужных рабочих данных, без входа и готового ответа. Учитываем копии и контейнеры. Число живых элементов не равно числу байтов процесса. Если ответ растёт, считаем его отдельно.

1. Queue: первым пришёл, первым ушёл

from collections import deque

q = deque()
q.append(5)
q.append(8)
q.append(2)          # q = [5, 8, 2]
print(q.popleft())   # вернёт 5, q = [8, 2]
q.append(7)          # q = [8, 2, 7]
print(q.popleft())   # вернёт 8, q = [2, 7]

Число 5 пришло первым и ушло первым. Число 8 пришло вторым и ушло вторым. Так работает очередь в столовой: новый ученик встаёт в конец, а обед получает тот, кто стоит в начале.

Правило. Queue: кладём в конец, берём из начала. Первым пришёл, первым ушёл.

Начало Queue называют головой, конец хвостом. Здесь 4 вызова append и 2 вызова popleft, всего 6 операций на концах за O(1) каждая. Дополнительная память: пик 3 элемента в q; вывод содержит 2 числа. Для m таких вызовов время O(m), память O(h), где h - наибольшая длина Queue. Последние два кадра показывают отдельный Deque из раздела 3.

2. Почему не list

Python list хранит ссылки как Array. Возьмите a = [5, 8, 2, 7, 4]. Вызов a.pop(0) забирает 5 и сдвигает 4 ссылки влево. Для длины s это s - 1 сдвигов, O(s) времени и O(1) дополнительной памяти.

Сумма сдвигов n(n - 1)/2 даёт O(n²) времени. У готового Deque n удалений дают O(n). Оба способа используют O(1) рабочего состояния сверх уже созданного контейнера; собираемый ответ потребовал бы O(n) мест. Преобразование deque(a) отдельно требует O(n) времени и O(n) дополнительной памяти.

Можно читать a[head] и делать head += 1: O(1) на шаг, O(n) на весь проход, O(1) дополнительной памяти. Но исходный list продолжает хранить старые ссылки. popleft() удаляет ссылку из Deque без сдвига остальных. Это не обещание немедленного уменьшения памяти процесса.

3. Deque: два конца

from collections import deque

d = deque([2, 4, 5])
d.appendleft(1)      # d = [1, 2, 4, 5]
print(d.pop())       # вернёт 5, d = [1, 2, 4]
d.append(7)          # d = [1, 2, 4, 7]
print(d.popleft())   # вернёт 1, d = [2, 4, 7]
ВызовЧто делаетВремя

В примере создание копирует 3 ссылки, затем идут 4 вызова на концах. Пик длины d равен 4, вывод содержит 2 числа. При создании временный list и d одновременно хранят по 3 ссылки. Для n исходных элементов и m вызовов на концах время O(n + m). Дополнительная память O(h), где h - наибольшая длина d; здесь h ≥ n. Чтение элемента использует O(1) рабочего состояния; len(d) стоит O(1).

Правило. Deque подходит для концов. Доступ к середине через list[i] стоит O(1). Перед удалением проверяйте if d:: пустой Deque вызывает IndexError.

4. Simulation: очередь за билетами

LeetCode 2073. tickets = [3, 1, 2]: человек 0 хочет 3 билета, человек 1 один, человек 2 два. Один билет покупают за 1 секунду. После покупки человек встаёт в конец, если ему нужны ещё билеты. Когда человек k = 0 купит последний билет?

from collections import deque

def time_required(tickets, k):
    q = deque(range(len(tickets)))   # номера людей
    time = 0
    while True:
        p = q.popleft()
        tickets[p] -= 1
        time += 1
        if p == k and tickets[p] == 0:
            return time
        if tickets[p] > 0:
            q.append(p)

print(time_required([3, 1, 2], 0))   # 6

В Queue лежат номера людей. Пусть b - число продаж до ответа. Создание Queue стоит O(n); цикл делает b удалений и не больше b добавлений: время O(n + b). Дополнительная память O(n), ответ - одно число. Код меняет входной tickets. Сохранение исходного входа через копию добавит O(n) времени и памяти.

Сохраните T = tickets[k] до изменений. Человек i ≤ k успевает купить min(tickets[i], T), а человек i > k - min(tickets[i], T - 1). Сложите эти n слагаемых одним проходом. Время O(n), дополнительная память O(1), ответ - число. Для [3, 1, 2] слагаемые 3, 1, 2 дают 6. Для [2, 3, 2], k = 0 слагаемые 2, 1, 1 дают 4: после последнего билета k остальные уже не покупают.

Обед, LeetCode 1700. В Simulation считайте подряд отказы от верхнего бутерброда. После успешной выдачи обнуляйте счётчик. Когда отказы достигли текущей длины Queue, остановитесь: этот бутерброд никто не хочет. Перед каждой выдачей возможен почти полный круг. Для n учеников время O(n²), дополнительная память O(n), ответ - число. Верх бутербродов храните как индекс в Array, без pop(0).

5. Круг и rotate

LeetCode 1823. Шесть друзей сидят по кругу, выбывает каждый третий. Храните круг в Deque: тот, с кого начинается счёт, стоит в начале. Друзья 1 и 2 остаются в игре. Друг 3 выбывает.

from collections import deque

d = deque([1, 2, 3, 4, 5, 6])
d.rotate(-2)         # d = [3, 4, 5, 6, 1, 2]
print(d.popleft())   # вернёт 3, d = [4, 5, 6, 1, 2]

Правило. Минус в rotate задаёт сдвиг влево, плюс - вправо. Для длины s > 0 CPython сокращает поворот r: a = r mod s, d = min(a, s - a). Время O(1 + d), дополнительная память O(1). Пустой Deque не меняется.

В коде Deque хранит 6 элементов; при создании ещё 6 ссылок временно занимает исходный list. Поворот имеет d = 2, удаление одно; вывод - одно число. Для всей игры пусть d_s = min((k - 1) mod s, s - ((k - 1) mod s)). Создание и n - 1 удалений плюс повороты дают O(n + ∑d_s), s от 2 до n. Худшая верхняя оценка O(n²); при постоянном k время O(n). Дополнительная память O(n), ответ - номер победителя.

Josephus Recurrence без хранения круга

Нумеруйте с нуля. J(1) = 0; J(s) = (J(s - 1) + k) mod s. После удаления одного игрока новая точка отсчёта смещена на k. Итеративно храните только текущее J; верните J(n) + 1. Это n - 1 обновлений, O(n) времени и O(1) дополнительной памяти. Для n = 6, k = 3 значения J: 0, 1, 1, 0, 3, 0. Победитель 1. Simulation удаляет 3, 6, 4, 2, 5; сумма d_s равна 7. Буквальное выполнение k - 1 переносов в каждом круге имеет оценку O(nk).

6. Greedy и Simulation на Deque

Codeforces 1579E1. Первое число добавьте в пустой Deque. Следующие сравнивайте с d[0]: меньшее кладите в начало, остальные в конец. Greedy оставляет как можно меньшее начало в Lexicographic Order. Для n чисел это n - 1 сравнений и n добавлений: O(n) времени. Deque хранит сам ответ из n чисел; дополнительное состояние O(1). Копия ответа в list потребует ещё O(n) памяти. При list.insert(0, x) убывающий вход даёт n(n - 1)/2 сдвигов, O(n²) времени.

LeetCode 950. Выполните Sorting карт, затем Simulation над Deque номеров мест 0..n - 1. Минимальную оставшуюся карту запишите на первое извлечённое место. Следующее место перенесите в конец. Время O(n log n): Sorting и O(n) действий Deque. Дополнительная память O(n) для номеров и Python Sorting; ответ отдельно O(n). Обратная Simulation тоже требует Sorting. Замена Deque на list с удалением начала может дать O(n²).

  3. Отдельно посчитайте создание контейнера, вызовы методов и повороты.
  4. Найдите пиковое число рабочих элементов и размер ответа.
