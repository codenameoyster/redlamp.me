Heap за O(log n) отдаёт наименьший элемент и принимает новый, а в Python с ним работают функции модуля heapq.

1. Зачем heap

В списке 100 000 чисел. Много раз нужно взять наименьшее число и добавить новое. Поиск минимума проходом стоит 100 000 шагов каждый раз. В отсортированном списке минимум стоит в начале, но вставка нового числа сдвигает соседей, как pop(0) в главе 1.

Heap хранит числа деревом. На первом уровне одно число, на втором два, на каждом следующем вдвое больше. 17 уровней вмещают 217 − 1 = 131 071 число, этого хватит для 100 000. Добавление и выдача идут по одному пути дерева и делают не больше 16 обменов.

Правило. Если много раз нужен наименьший элемент, а элементы приходят и уходят, берите heap. heappush и heappop работают за O(log n), h[0] за O(1).

2. Дерево в списке

Heap в heapq это обычный список. Возьмите h = [1, 3, 2, 5, 9, 8]. Место 0 это корень дерева. Дети места 0: места 1 и 2. Дети места 1: места 3 и 4, числа 5 и 9. У места 2 один ребёнок, место 5.

Дети места i стоят на местах 2i + 1 и 2i + 2. Родитель места i стоит на месте (i − 1) // 2.

Правило. В heap родитель не больше своих детей. Поэтому h[0] наименьший. Остальной порядок не задан: h[-1] не обязательно наибольший, и список не обязательно отсортирован.

3. heappush и heappop

import heapq

h = [1, 3, 2, 5, 9, 8]
heapq.heappush(h, 0)
print(h)                  # [0, 3, 1, 5, 9, 8, 2]
print(heapq.heappop(h))   # 0
print(h)                  # [1, 3, 2, 5, 9, 8]

heappush кладёт число в конец и поднимает его: пока число меньше родителя, они меняются местами. heappop забирает корень, ставит туда последний элемент и спускает его: меняет с меньшим ребёнком, пока этот ребёнок меньше. Правого ребёнка может не быть, поэтому спуск сначала проверяет, что место 2i + 2 есть в списке.

heapq.heapify(a) делает heap из списка на месте за O(n): [5, 3, 8, 1, 9, 2] станет [1, 3, 2, 5, 9, 8]. Функция возвращает None, поэтому пишите heapq.heapify(a), а не a = heapq.heapify(a).

Правило. Подъём и спуск идут по одному пути дерева, поэтому heappush и heappop стоят O(log n). heapify строит heap за O(n).

4. Heap на максимум через минус

В heapq есть только heap на минимум. Возьмите числа 6, 4, 9: наибольшее из них 9. Среди −6, −4, −9 наименьшее −9. Значит, если класть числа с минусом, в корне окажется наибольшее число со знаком минус.

import heapq

h = []
for x in [6, 4, 9]:
    heapq.heappush(h, -x)
print(h)                 # [-9, -4, -6]
top = -h[0]              # 9
y = -heapq.heappop(h)    # 9, h = [-6, -4]
print(top, y, h)         # 9 9 [-6, -4]

Правило. Heap на максимум: кладите −x, читайте −h[0], доставайте −heappop(h). Минус нужен при записи, при чтении и при каждом heappop.

queue.PriorityQueue нужен, когда несколько частей программы работают одновременно. В задачах берите heapq.

5. Камни: модель главы

LeetCode 1046. Камни [6, 4, 9, 2]. Каждый ход берёт два самых тяжёлых камня. Если веса разные, разница возвращается в heap.

import heapq

stones = [6, 4, 9, 2]
h = [-s for s in stones]
heapq.heapify(h)
while len(h) > 1:
    y = -heapq.heappop(h)
    x = -heapq.heappop(h)
    if y != x:
        heapq.heappush(h, -(y - x))
print(h)   # [-1]

Допишите ответ сами: что вернуть, если в heap остался один камень, и что, если heap пуст?

6. Кортежи: приоритет и ничья

Сравните (2, 'b') и (2, 'c'). Первые элементы равны, поэтому Python сравнивает вторые: 'b' < 'c'. Значит, (2, 'b') < (2, 'c'). А (1, 'z') < (2, 'a'): 1 < 2, и до букв сравнение не доходит.

Правило. Кортежи сравниваются по первому элементу, при равенстве по второму, и так дальше. Положите в heap кортеж: сначала приоритет, потом то, что решает ничью, и heapq выдаст элементы в нужном порядке.

В LeetCode 3264 при равных числах берут первое: кортеж (число, номер) решит ничью. В LeetCode 692 слова идут «чаще раньше, при равной частоте по алфавиту»: это кортеж (−частота, слово). Если приоритеты равны, а дальше лежит словарь, Python сравнит словари и выдаст TypeError. Ставьте номер перед объектом: (приоритет, номер, объект).

7. k-е по величине: heap размера k

Найдём третье по величине в [7, 2, 9, 4, 6, 1, 8]. Держим heap на минимум из 3 самых больших чисел, которые уже видели. Вершина h[0] самая слабая из трёх. Новое число больше вершины вытесняет её: heapq.heapreplace(h, x) достаёт вершину и кладёт x за один вызов. Число не больше вершины пропускаем.

Правило. Для k-го по величине держите heap на минимум размера k. В конце его вершина и есть ответ. Время O(n log k), память O(k).

8. Что нужно запомнить

  • h[0] наименьший, а h[-1] не обязательно наибольший.
  • heapify возвращает None: не пишите h = heapq.heapify(h).
  • Сначала heap, потом число: heappush(h, x).
  • Heap на максимум: минус при записи, при чтении и при каждом heappop.
  • Кортеж (приоритет, номер) решает ничью.
  • Повторы в k-м по величине считаются: в [5, 5, 4] второе по величине 5.

9. Как решать задачи этой главы

  1. Найдите повтор «взять наименьшее или наибольшее, добавить новое». Это работа для heap.
  2. Решите, что лежит в heap: число, −число или кортеж (приоритет, то, что решает ничью).
  3. Прогоните heap на примере из условия на бумаге: что лежит в h после каждого шага.
  4. Посчитайте операции. n раз heappush и heappop стоят O(n log n), а лимит 2 с на пример, 3 с на скрытый тест.
