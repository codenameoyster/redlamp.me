Binary Heap реализует Priority Queue: извлекает элемент с лучшим приоритетом. В Python функции heapq работают с list; они поддерживают Min-Heap и Max-Heap.

1. Зачем Binary Heap

Пусть h - текущая длина Binary Heap, n - число входных элементов. Сначала считаем сравнения чисел ограниченного размера за O(1). Длина пути к корню не больше floor(log₂ h). Для h = 100 000 высота равна 16: всего 17 уровней, в которых помещается до 131 071 элемента.

Выбор минимума и обновление при h = 100 000
СпособСчитаемая работаВремя
Linear Scan99 999 сравнений для одного минимумаO(h)
Отсортированный listдо 99 999 сдвигов при удалении началаO(h)
Min-Heapпуть до 16 рёбер; O(1) сравнений на реброO(log(h + 1))

Дополнительная память: Linear Scan хранит один лучший индекс, O(1). Скопированный Binary Heap хранит O(n) элементов; работа с готовым h требует O(1) временного состояния. Python Sorting может требовать O(n) рабочих ссылок. Ответ-минимум занимает O(1).

Правило. Чтение h[0] стоит O(1). Обновления heappush, heappop и heapreplace требуют O(log(h + 1)) сравнений. Изменение размера list учитываем амортизированно: отдельное расширение может копировать O(h) ссылок.

2. Tree в list

Возьмите h = [1, 3, 2, 5, 9, 8]. Место 0 - корень Tree. Дети места 0: места 1 и 2. Дети места 1: места 3 и 4, числа 5 и 9. У места 2 один ребёнок, место 5. Рисунок показывает один list двумя способами; второй копии в алгоритме нет.

Дети места i стоят на местах 2i + 1 и 2i + 2. Родитель места i стоит на месте (i − 1) // 2.

Правило. В Min-Heap родитель не больше своих детей. Поэтому h[0] наименьший. Остальной порядок не задан: h[-1] не обязательно наибольший.

Проверка свойства по всем детям требует n - 1 сравнений: для 6 элементов их 5. Время O(n), дополнительная память O(1), результат - True или False. Формулы индексов и чтение корня требуют O(1) времени и памяти.

3. heappush и heappop

import heapq

h = [1, 3, 2, 5, 9, 8]
heapq.heappush(h, 0)
print(h)                  # [0, 3, 1, 5, 9, 8, 2]
print(heapq.heappop(h))   # 0
print(h)                  # [1, 3, 2, 5, 9, 8]

heappush добавляет число в конец и восстанавливает порядок к корню. Учебная модель меняет его с родителем, пока оно меньше. Для удаления модель ставит последний элемент в корень и меняет его с меньшим ребёнком. Правого ребёнка может не быть. Реализация CPython использует перемещения и может сначала пройти до листа, затем подняться; рисунок считает обмены учебной модели, а не инструкции Python.

В примере один push и один pop: O(log(n + 1)) работы после создания исходного list за O(n). Пик длины h равен 7, дополнительное состояние обновлений O(1). Печать двух состояний по n элементов сама стоит O(n) времени и даёт O(n) выводимых значений.

Heapify: почему O(n), а не O(n log n)

heapq.heapify(a) строит Min-Heap на месте: [5, 3, 8, 1, 9, 2] станет [1, 3, 2, 5, 9, 8]. Функция возвращает None. Вызов обрабатывает родителей снизу вверх; листья уже упорядочены. Для большинства вершин путь короткий.

Полный Binary Heap из 15 элементов: предел спуска по рёбрам
Высота вершиныВершинВсего рёбер спуска

Итого1511

На ребро приходится O(1) сравнений. Сумма ограничена n(1/4 + 2/8 + 3/16 + …) = O(n). Число 11 - предел рёбер учебного спуска, не точное число сравнений heapq. Heapify требует O(n) времени и O(1) дополнительной памяти для готового list. Копия входа добавляет O(n) памяти; отдельного ответа нет.

Альтернатива - n последовательных heappush: O(n log(n + 1)) времени и O(n) мест нового Binary Heap. Для 15 убывающих чисел подъёмы проходят ровно 2 · 1 + 4 · 2 + 8 · 3 = 34 ребра.

4. Max-Heap и отрицательные числа

Python 3.14 поддерживает heapify_max, heappush_max, heappop_max и heapreplace_max. Их оценки такие же, как у Min-Heap. Например, Heapify для [6, 4, 9] создаёт Max-Heap [9, 4, 6]; один pop возвращает 9. Построение O(n), извлечение O(log(n + 1)), рабочая память O(1) сверх готового list.

Для чисел подходит и смена знака: среди -6, -4, -9 минимально -9. Следующий код использует Min-Heap для выбора максимума.

import heapq

h = []
for x in [6, 4, 9]:
    heapq.heappush(h, -x)
print(h)                 # [-9, -4, -6]
top = -h[0]              # 9
y = -heapq.heappop(h)    # 9, h = [-6, -4]
print(top, y, h)         # 9 9 [-6, -4]

Код делает 3 вставки и 1 удаление. Для n чисел повторные вставки дают O(n log(n + 1)) времени; дополнительная память O(n) для h, пик здесь 3. Вывод состояний занимает O(n) значений. Создание [-x for x in a] с последующим Heapify даёт O(n) времени и O(n) памяти; каждый знак меняется один раз.

Построение для [6, 4, 9] и одно извлечение максимума
СпособСозданиеУдалений / пик длины
Отрицательные веса, как в коде3 push1 / 3

Правило. Max-Heap выбирает максимум напрямую. При хранении отрицательных чисел используйте -x при записи, -h[0] при чтении и -heappop(h) при удалении.

queue.PriorityQueue нужен, когда несколько частей программы работают одновременно. В задачах берите heapq.

5. Камни: Simulation с Max-Heap

LeetCode 1046. Камни [6, 4, 9, 2]. Каждый ход берёт два самых тяжёлых камня. Если веса разные, разница возвращается в Min-Heap с отрицательным знаком.

import heapq

stones = [6, 4, 9, 2]
h = [-s for s in stones]
heapq.heapify(h)
while len(h) > 1:
    y = -heapq.heappop(h)
    x = -heapq.heappop(h)
    if y != x:
        heapq.heappush(h, -(y - x))
print(h)   # [-1]

Для n камней создание и Heapify стоят O(n). Каждый круг уменьшает длину хотя бы на 1: не больше n - 1 кругов, по 2 pop и не больше 1 push. Время O(n log(n + 1)); дополнительная память O(n) для отрицательных весов. Ответ - одно число, -h[0] или 0. В примере 3 круга, 6 pop, 3 push, пик 4 элемента.

Почему не Sorting на каждом круге

Общая верхняя оценка повторного Sorting: O(n² log(n + 1)), потому что кругов O(n), а длина каждого входа не больше n. Python может использовать порядок прошлого круга, поэтому эта оценка не утверждает точную работу. Дополнительная память Sorting до O(n). Повторный Linear Scan двух максимумов даёт O(n²) времени, до O(1) рабочего состояния при изменении входного list. В нашем примере длины перед кругами равны 4, 3, 2.

6. tuple: приоритет и ничья

Сравните (2, 'b') и (2, 'c'). Первые элементы равны, поэтому Python сравнивает вторые: 'b' < 'c'. Значит, (2, 'b') < (2, 'c'). А (1, 'z') < (2, 'a'): 1 < 2, и до букв сравнение не доходит.

Число просмотренных полей tuple, не инструкций Python
ПараПолейРабочая память / ответ
(2, b) и (2, c)2O(1) / True
(1, z) и (2, a)1O(1) / True

Правило. tuple сравнивается по полям до первого различия. Используйте (приоритет, уникальный номер, объект), чтобы Python не пытался сравнить два dict через <. Сравнение пары ограниченных чисел стоит O(1) времени и памяти. Сравнение двух слов длины до L может читать O(L) символов.

LeetCode 3264. Пары (число, индекс) выбирают первое из равных чисел. Пусть t - число умножений. Heapify n пар и t замен дают O(n + t log(n + 1)) времени, O(n) дополнительной памяти. Результат содержит n чисел; запись обратно в nums использует входные места. Для [2, 1, 3, 5, 6], t = 5, multiplier = 2: 5 замен корня и 5 записей, пик 5 пар, ответ [8, 4, 6, 5, 6].

При t ≤ 10 простой Linear Scan разумен: t(n - 1) сравнений, O(n + tn) времени с выводом n чисел, O(1) рабочего состояния при изменении nums. В этом примере 20 сравнений. Сравнивайте строго через <, чтобы сохранить первый индекс при равенстве.

LeetCode 692: частые слова и стоимость сравнения

Пусть n - число слов, u - число разных слов, S - число всех входных символов, L - максимальная длина слова. Counter считает частоты; затем Heapify строит u пар (-частота, слово), и k вызовов heappop собирают ответ. Ожидаемое время O(S + uL + kL log(u + 1)) учитывает Hash Table и сравнения слов при равных частотах. При ограниченной L: O(n + u + k log(u + 1)). Дополнительная память O(u) ссылок и счётчиков, ответ O(k) ссылок; сами слова не копируются.

Для [b, a, b, c, a]: n = S = 5, u = 3, L = 1. Нужны 5 обновлений Counter, Heapify 3 пар и 2 pop. Пик: 3 записи Counter и 3 пары; ответ [a, b] хранит 2 ссылки. Sorting всех u пар даёт ожидаемое O(S + Lu log(u + 1)) времени и O(u) рабочей памяти. Binary Heap размера k уменьшает работу выбора до O(uL log(k + 1)), но Counter всё равно хранит O(u) записей. Нужен обратный порядок для равных частот в корне и Sorting выбранных k слов перед выводом.

7. k-е по величине: Min-Heap размера k

Найдём третье по величине в [7, 2, 9, 4, 6, 1, 8]. Держим Min-Heap из 3 самых больших чисел, которые уже видели. Вершина h[0] - наименьшее из этих трёх. Если новое число больше вершины, heapq.heapreplace(h, x) заменяет её. Иначе число пропускаем.

Здесь 3 начальных push, 4 сравнения новых чисел с корнем, 3 замены. Пик 3 элемента, ответ 7. В общем время O(n log(k + 1)), дополнительная память O(k), ответ O(1). Первые k чисел можно скопировать и обработать Heapify за O(k). Повторы считаются: в [5, 5, 4] второе по величине равно 5.

Sorting и Quickselect для одного ответа

Sorting всего Array требует O(n log(n + 1)) времени и до O(n) дополнительной памяти Python. Итеративный Quickselect со случайным выбором опорного элемента даёт ожидаемое O(n) времени, но O(n²) в худшем случае. При разбиении на месте ему достаточно O(1) дополнительного состояния; копия для сохранения входа добавит O(n). Min-Heap подходит, когда данные приходят постепенно и нужно хранить только k лучших.

8. Greedy и доступность бонусов

Codeforces 1800C2. Идите по колоде сверху вниз. Положительный бонус добавляйте в Max-Heap. Для героя с силой 0 берите наибольший доступный бонус, если он есть. Каждый бонус входит один раз и выходит не больше одного раза: O(n log(n + 1)) времени и O(n) дополнительной памяти для n карт. Ответ - одна сумма. Для [4, 1, 0, 7, 0, 0] нужны 3 push и 3 pop, пик 2 бонуса, сумма 12.

Почему Greedy допустим: бонус можно сбросить, а герои равнозначны. Замена выбранного меньшего доступного бонуса на больший не уменьшает сумму текущего и будущих героев. Linear Scan всех доступных бонусов на каждого героя даёт O(n²) времени. Sorting всей колоды нарушает доступность: в [0, 9] герой не может взять будущий бонус, ответ 0.

9. Как проверять стоимость

  1. Определите приоритет и правило равенства.
  2. Отдельно посчитайте построение, обновления и вывод.
  3. Укажите наибольшую длину Binary Heap и цену сравнения ключей.
  4. Проверьте временные копии и отделите память ответа.
